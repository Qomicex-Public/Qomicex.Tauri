# 插件签名验证（ADR-050）兼容与降级策略

## 信任链

Ed25519 三级信任链：
1. **商店根钥**（`PLUGIN_ROOT_PRIVATE_KEY` / `PLUGIN_ROOT_PUBLIC_KEY` CF Worker secret）签发开发者公钥证书
2. **开发者密钥**签每个 release 的包体（`signature.json`）
3. **包内嵌证书**（`signature.cert.json`），启动器用内置根公钥完全离线验签

## 强制范围

| 路径 | 签名要求 | 备注 |
|------|---------|------|
| 商店新上传版本（`POST /:id/versions`） | **强制** | 无签名或验签失败 → 422 |
| 启动器手动上传（`POST /api/plugins/upload`） | **强制** | 无签名或验签失败 → 拒绝 |
| 启动器商店安装（`/api/store/install`） | **有签名则验** | 无签名放行（老版本兼容） |
| 本地开发目录安装（`install_from_dir`） | **不强制** | `plugins-dev/` 开发路径 |

## 降级策略

1. **老版本不强制重签**：已有商店版本（无签名）继续可安装，不需要重新打包签名。
2. **未配根钥的商店**：`PLUGIN_ROOT_PUBLIC_KEY` 未设置时，新版本上传被拒（`signature_invalid`，原因 "商店未配置签名根公钥"）。需运行 `scripts/plugin-keygen.mjs generate` 生成根钥并配置为 Worker secret。
3. **启动器根钥常量**：`src-backend/qomicex-backend/src/services/plugin_signature.rs` 的 `ROOT_PUBLIC_KEY_B64` 必须与商店的 `PLUGIN_ROOT_PUBLIC_KEY` 一致。更换根钥需同步更新两端。
4. **密钥撤销**：开发者通过 `DELETE /api/v1/developer/keys/me` 撤销密钥后，旧证书签名的版本无法再上传（但已在商店中的版本不受影响）。
5. **私钥泄露**：开发者重新生成密钥对，上传新公钥（`POST /api/v1/developer/keys`），旧证书自动失效。商店仅接受新证书签名的版本。

## 签名格式

`signature.json`（包内根目录）：
```json
{
  "alg": "Ed25519",
  "signedHash": "<sha256 hex>",
  "signerKeyId": "<key id>",
  "signature": "<base64 ed25519 sig>"
}
```

`signature.cert.json`（包内根目录）：
```json
{
  "alg": "Ed25519",
  "keyId": "<key id>",
  "developerId": "<user id>",
  "developerName": "<username>",
  "publicKey": "<base64 raw pubkey>",
  "issuedAt": "<ISO8601>",
  "signature": "<base64 ed25519 sig by root>"
}
```

`signedHash` = SHA-256(canonical JSON 的 `{ manifest: sha256Hex(manifest.json 原始字节), files: [{path, sha256}] }`)。规范化：递归按键排序 + 无空白 JSON。

## 开发/测试

- 测试根钥与 launcher 内置根公钥 CODE 值一致（`PLUGIN_ROOT_PRIVATE_KEY` / `ROOT_PUBLIC_KEY_B64`）。
- 生成方式：`node scripts/plugin-keygen.mjs generate`，privateKey 设 wrangler secret，publicKey 设 wrangler var 并内嵌到 launcher 常量。
- 可在 src-backend 运行 `cargo test plugin_signature` 验证签名模块。
- 可在 store 运行 `pnpm test signature.test.ts` 验证签名 API。
