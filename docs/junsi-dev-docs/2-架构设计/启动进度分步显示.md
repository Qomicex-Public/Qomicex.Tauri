# 启动进度分步显示（8 步细化）

## 概述

启动进度弹窗（`LaunchProgressDialog`）的固定步骤从 4 步细化为 8 步，每步映射后端/core 真实执行阶段；条件性步骤未发生时显示灰色 skipped 态而非误导性绿勾。

## 步骤与 stage 映射

| # | 行（i18n 键） | stage | 来源 |
|---|---|---|---|
| 1 | Java 环境（java） | `java` | 前端预检/自动下载（见《启动前Java检查与自动下载》） |
| 2 | 验证账户（logging-in） | `auth` | 前端在调启动 API 前注入快照——后端 handler 同步段执行 `refresh_microsoft_token`（网络调用，可达数秒），恰好覆盖该窗口 |
| 3 | 检查文件完整性（checking） | `starting` / `checking` | 后端 instance.rs |
| 4 | 补全文件（repairing） | `repairing` | 后端，条件性（有缺失文件才发生），行内文件数百分比 |
| 5 | 准备环境（preparing） | `preparing` | 后端（写游戏语言 + 选 Java 运行时） |
| 6 | 解压原生库（natives） | `natives` | **core 回调**：`launch_inner` 解压 natives 前 |
| 7 | 构建启动参数（building） | `params` | **core 回调**：`select_params` 前 |
| 8 | 启动游戏（launching） | `launching` | 后端 spawn 成功后（95%）、`running` 100% 前的短暂确认 |

## core 机制（qomicex-core-rust）

- `LaunchOptions` 新增 `#[serde(skip)] on_stage: Option<LaunchStageCallback>`（`Arc<dyn Fn(&str) + Send + Sync>`）；`Debug`/`PartialEq` 改手写实现（排除回调字段），不参与序列化与相等比较
- `launch_inner` 在 `unzip_natives` / `select_params` 前回调 `"natives"` / `"params"`
- 后端把回调映射为 `LaunchTracker` 进度快照（natives 55% / params 80%），instance.rs 与 connector.rs（联机代启）均接入

## skipped 灰态

- `InstallStepInfo.status` 新增 `'skipped'`；`InstallStepsList` 渲染 `CircleDashed` 灰图标
- `LaunchProgressDialog` 维护 `seenStagesRef`（本会话出现过的 stage 集合，dialog 关闭时清空）；已越过的行若其阶段从未出现 → skipped（如无缺失文件时的"补全文件"、联机代启流中的"检查文件完整性"）
- 取代旧逻辑"active 行之前的行一律绿✓"，消除未发生步骤的误导

## 时序与兼容性

- 后端不再在调 `core.launch()` 前写 `launching`（旧行为会让 natives/params 回调造成步骤行"回跳"）；`launching` 移到 spawn 成功后写（95%）
- connector 房主代启：移除 2s 假心跳（`launching（检查/下载文件）`），由真实回调替代；`build_launch_options` 返回后补设 `on_stage`
- 联机代启流不经过 checking/repairing/preparing（完整性检查在 core 内部无独立上报），对应行显示 skipped——与真实执行一致
- i18n 零新增：`logging-in`/`natives`/`building` 复用既有（曾为死键）翻译

## 已知边界

- 联机代启的"验证账户"在 poll 启动前已执行完，行显示 skipped（实际已运行）——可见窗口极短，接受
- core.launch 真实耗时集中在 natives/params/spawn，步骤推进为亚秒级闪烁属预期
