## 1. 插件扩展设计：进程隔离 / 协议 / 生命周期 / WASM 取舍

### 1.1 冻结问题的真相

WebView2/Chromium 中 **iframe 与宿主共享同一 renderer 进程、同一主线程事件循环**。因此隔离手段与防冻结能力并不等价：

| 隔离手段 | DOM/CSS 隔离 | 防 UI 冻结 | 成本 |
|---|---|---|---|
| 内联渲染（现状默认） | ❌ | ❌ | 0 |
| iframe l2 | ✅ | ❌（busy-loop 仍卡整个启动器） | 低 |
| 独立 WebView 窗口（新 l4） | ✅ | ✅（独立 renderer 进程，可杀） | 中 |
| WASM l3（wasmtime，进程外 Rust） | ✅（无 UI） | ✅（计算天然不占 UI 线程） | 中 |

**结论**：`while(true)` 在内联或 iframe 里都会冻死主 UI。真正"绝不卡顿"只能靠两件事：
1. **UI 插件一律 iframe（l2）作为默认**——解决 DOM 污染、CSS 泄漏、同源窃取（opaque origin）；
2. **重计算永远离开 UI 主线程**——规则层强制：Web Worker（iframe 内独立线程）/ WASM / 后端代理三选一，禁止插件主线程跑长循环。`qomicex verify` 静态告警把关。

### 1.2 l4 远程 WebView（独立宿主进程的现实落地）

若插件必须自带重 UI 且不可控（第三方渲染器等）→ 新增 **l4 远程 WebView**：Tauri 次 `WebviewWindow` 托管插件，天然 renderer 进程隔离，经后端 IPC 通信；冻结可杀。注意：这是 OS 级 renderer 进程隔离，**不是 sidecar Node 进程**——Tauri 侧用第二 WebView 比 sidecar 便宜且能渲染 UI。

- **定位**：Phase 1 渐进项，作为重 UI 插件的按需升级通道（manifest `layers` 含 `l4` 或 `webview: true` 标记）。
- 需要配套：窗口生命周期管理、跨窗口 postMessage 中转（复用 `__pluginRegistry` 模式）、冻结检测与杀进程。

### 1.3 插件协议 v2

- `manifest.schemaVersion = 2`，bridge 加 `protocolVersion`，缺省兼容 v1。
- 统一生命周期（对齐 l3 已有 `on_load/on_unload`）：

```
activate(ctx)         // async + 3s 超时 + error boundary：失败→捕获→禁插件→toast，绝不上抛卡 UI
deactivate()          // async 清理
viewShow()/viewHide() // 页面可见性（tab 切换）
configChange(patch)   // settings 变更订阅（新增）
updateAvailable(v)    // 配合商店灰度（新增）
```

- 桥方法按 `METHOD_PERMISSIONS` 不变；iframe 内 `apiBridgeScript` 与 `sourceMap` 沿用现状（`sandbox.ts:93`）。
- 错误语义：所有桥调用 reject 带 `{code, message}`，禁 throw 到宿主。

### 1.4 WASM 沙箱定位（安全 vs 性能取舍）

| 维度 | WASM(l3, wasmtime) | iframe(l2) | l4 WebView |
|---|---|---|---|
| 安全 | 最优：无 DOM/无系统调用，host 函数白名单 | 中：有 DOM，opaque origin | 低：全浏览器能力 |
| 性能 | 计算快，无渲染 | 渲染快 | 渲染快，进程开销大 |
| 适用 | 无 UI 工具（网络代理、解析、批处理） | 标准 UI 插件（**默认**） | 重 UI 插件 |
| 内存 | wasmtime 在 Tauri 主进程，需实例配额 | 低 | 每窗口 ~100MB 级 |

结论：**l3 只做无 UI 计算插件**，不扩展渲染能力；wasmtime 实例加内存/CPU 配额与 `on_load` 超时。

## 2. 主题与视觉语义化

### 2.1 三级语义 Color Tokens

现状是平铺 HSL 变量（`--accent-foreground`）。升级为三级结构：

```
primitives（原始色板）→ semantic（语义）→ component（控件级，仅组件内部）
```

语义 token 采用点分命名，与插件 UI 全链路统一：

```
foreground / foreground.muted / foreground.accent / foreground.destructive
background / background.elevated(浮层) / background.emphasis(高亮) / background.sunken
border / border.strong / border.accent
accent / accent.hover / accent.active / accent.foreground
status.success / status.warning / status.error        // 游戏/下载状态语义
```

非色 token 一并纳入规范：`radius.*`、`space.*`、`font.family/size/weight`、`motion.duration/easing`（并入现有 `--anim-duration-multiplier`）、`shadow.*`、`glass.blur/saturation`（对齐 ADR-035/036）。

### 2.2 主题包格式 `.qtheme`

```
theme.json      // schema v1：tokens + contributions 声明（zod 校验）
theme.css       // 可选：命名空间原始 CSS 注入（禁止裸全局，须 --qtx-theme 前缀或 scoped）
theme.mjs       // 可选：CSS-in-JS 计算层，沙箱执行，读启动器配置(accent/背景)推导派生 token → 真正"动态样式"
icon-theme.json // 可选：图标主题
fonts/          // 可选：含许可声明的字体
```

三类**贡献（contributes）**对齐 VS Code：
- **颜色主题**：token 全量映射（插件 UI 与启动器同源 → 原生控件全局换肤，无需重建 plugin-ui）
- **图标主题**：`{ "plugin-ui 图标名": "path/svg | codepoint | url" }`，启动器 `Icon` 组件统一消费
- **字体/连字**：字体资源 + `font-feature-settings` 按作用域（日志控制台、版本 diff、编辑器类插件）

### 2.3 与 `@qomicex/plugin-ui` 的"原生级控件"接入

硬性约定：**plugin-ui 组件只允许 `var(--*)` 消费 token，禁止内联色值**。主题管理器运行时在 `:root`/`data-theme` 写 CSS 变量 → 换主题 = 全组件（含已打包 dist）即时换肤，且**消除"改组件须重建 dist"的陈旧问题**。`theme.mjs` 沙箱内只暴露只读配置 + 计算函数，无网络/无 DOM。

## 3. 生态市场与可持续增长

### 3.1 签名验证

- **Ed25519 三级信任链**：商店根钥签发开发者公钥（GitHub 组织验证后自动入 D1 `developer_keys`）→ 开发者密钥签每个 release。
- 包内 `signature.json = { alg, signedHash, signerKeyId, signature }`，`signedHash` 为**规范化 manifest+文件清单的 SHA-256**（规定 JSON 键序/无空白，保证可复现哈希）。
- 启动器在安装/更新时验签（离线注册表仍需商店根钥缓存）；上传端（`lib/qplugin.ts` 已有 zip-slip）加签名校验。

### 3.2 依赖版本与冲突

- semver 范围解析 + 启动器维护**已安装依赖 DAG**；共享依赖选最大兼容版本，无法满足 → 安装时阻塞并 UI 列出冲突插件（不做自动降级魔法；依赖树升级时再引入求解器）。
- 商店强制：**有依赖者的版本不可撤下**（D1 约束 + 接口校验）。

### 3.3 灰度升级

- 发布通道 `stable / beta / alpha`（对齐启动器自身版本语义）；每版本 `rolloutPercent`。
- 启动器新增**更新轮询**：拉 `/check-updates`（按 launcher 版本+插件版本缓存），提示升级；接入 opt-in 崩溃/错误遥测 → 异常率超阈值自动暂停灰度。

### 3.4 Cloudflare Worker 额度与社区化

| 阶段 | 动作 | 效果 |
|---|---|---|
| A（现在） | **下载永不流经 Worker**：`/api/download/url` 返回签名 R2 URL，启动器直连 `cdn.qomicex.top` | 下载量对请求配额≈0 |
| A | 读接口（catalog/detail/check-updates）加 `Cache-Control`，走 Cloudflare 边缘缓存 | 热门读 = 缓存命中，不计 Worker CPU |
| B（增长） | 前台重度读页预渲染到 R2 + ISR 式再验证 | 读流量几乎全部 CDN |
| C（社区） | **开放注册表规范**（对标 Open VSX）：启动器已有 `registryUrl` 多源能力，公布规范后第三方可自建镜像 | CF 额度死路封死，社区接管读流量 |

成本诚实项：CF 付费 $5/月 10M 请求，只要下载不走 Worker + 读走缓存，社区启动器读流量远够；真正的配额杀手只有"下载过 Worker"和"写侧滥用"（已有限流+认证）。

## 5. 附加：性能陷阱与技术债清单

| # | 陷阱/债 | 后果 | 修复 |
|---|---|---|---|
| 1 | **内联渲染为默认** | busy-loop 冻结整个启动器 | 默认切 iframe + 主线程计算禁令 |
| 2 | 插件 `theme.css` 裸全局注入 | 插件样式污染启动器 | 命名空间/scoped + iframe 化缓解 |
| 3 | 权限校验纯客户端，内联同源 | 一插件 XSS = 全量沦陷 | iframe opaque origin + 桥 origin 校验 |
| 4 | 无签名验证 | 供应链投毒（社区上传即触发） | 3.1 Ed25519 链 |
| 5 | 无插件更新/灰度通道 | 安全修复无法下发 | 3.3 更新轮询 |
| 6 | 商店下载可能过 Worker | 配额耗尽 | 3.4 signed R2 直连 |
| 7 | plugin-ui dist 陈旧 | 改组件不生效 | token 化后组件不再内嵌颜色，降低重建频率 |
| 8 | 主 renderer 单体：首屏+动画+插件同线程 | gsap/backdrop-filter 互斥已踩坑(ADR-037) | 动画 compositor-only + 重活下线 |
| 9 | wasmtime 在主进程无配额 | 大 WASM 实例拖垮启动器 | 实例配额 + 加载超时 |
| 10 | 安装覆盖式无回滚快照 | 升级坏插件无法还原 | 保留上一版本快照 |

## 任务① 插件默认渲染切到 iframe(l2) — 实现记录

**状态**：已实现并验证（Playwright Tauri mock 法）

**变更**：
- 新增 manifest 可选字段 `render?: 'inline' | 'iframe'`
- **默认**（无 `render` 字段）→ iframe 沙箱（`createSandbox`，`sandbox="allow-scripts"`），与声明 `l2` 行为一致
- `"render": "inline"` → 显式 opt-in 走内联（`renderInline`），旧插件兼容（现有 l2 插件行为不变）
- 纯 CSS 插件（`l0`/`l1` 无 `frontend`）不进入渲染分支，CSS 注入逻辑不变
- 后端 Rust `PluginManifest` 同步增加 `render: Option<String>`（否则 serde 序列化回前端时字段被丢弃，`render:"inline"` 失效）

**涉及文件**：
- `src/plugins/types.ts` / `packages/plugin-ui/src/plugins.ts`：类型加 `render`
- `src/plugins/plugin-loader.tsx:67`：`useSandbox = plugin.manifest.render !== 'inline'`
- `src-backend/qomicex-backend/src/services/plugin.rs`：`PluginManifest` 加字段

**验证记录**（Playwright 注入 Tauri mock + 独立后端 5011 转发，见 `docs/junsi-dev-docs/2-架构设计/前端浏览器调试-Playwright-Tauri-mock注入.md`）：
- 无 l2 有 frontend 插件 → 挂载 `<iframe sandbox="allow-scripts">`，`about:srcdoc`，桥注入完整（`__PLUGIN_API__`/`__pluginRegistry`）
- 桥全链路：iframe 内 `__PLUGIN_API__.call('showToast', ...)` → postMessage → 主窗口 `sourceMap` → `executePluginMethod` → 权限校验 → `plugin:show-toast` CustomEvent ✓
- 纯 CSS(l0) 插件 → `style[data-plugin-theme]` 注入 ✓（不回归）
- 插件持续运行（`setInterval` 高频循环）时主 UI 可交互 ✓
- `render:"inline"` 插件 → 内联容器渲染、无 iframe ✓
- `pnpm run build`（tsc strict + vite）通过 ✓

**已知限制**：`sandbox="allow-scripts"`（无 `allow-same-origin`）iframe 内同步 `while(true)` 死循环仍可能阻塞共享渲染进程（Chromium srcdoc iframe 同源继承父进程模型）；setTimeout 异步循环不受影响。跨进程隔离不在本任务范围。

## 任务⑤ qomicex CLI 脚手架 — 实现记录

**状态**：已实现并验证（零依赖 Node ≥ 20，pnpm workspace 成员 `packages/qomicex-cli`）

**命令**：
- `create <id>`：从内置模板生成合法插件项目（Vite+React+TS+Tailwind+@qomicex/plugin-ui），模板 `layers:["l2"]`，权限最小集 `config:read / ui:toast / network:cors_proxy`。生成项目自带 `pnpm-workspace.yaml` 独立 workspace root，可 `pnpm install && pnpm run build` 通过。
- `dev`：起 Vite dev server + 写 `.qomicex-dev.json` 配置（v1 不自动挂载启动器，仅输出配置产物）。
- `pack`：`tsc && vite build` → 手动 copy 入口根文件（theme.css/overlay.html）→ 手写 zip（CRC32+deflateRaw，与 fflate 兼容）→ `.qplugin`。`--key` 选签名（signature.json 仅，无 cert 则 warning）。
- `verify`：目录模式（manifest 手写校验 + 权限最小化 `METHOD_PERMISSIONS` 表 + `while(true)` 长循环启发式）与包模式（manifest + 签名 Ed25519 验签，内置商店根公钥）。
- `publish`：设备流（RFC 8628）→ developer/keys 注册公钥获取证书 → 签名包 → multipart 上传。`--key` 或 `QOMICEX_SIGN_KEY` 环境变量。

**签名规范化**：与 store `src/lib/signature.ts` / launcher `plugin_signature.rs` 字节级一致（canonicalJson 键序/无空白，signedHash = 载荷 SHA-256）。端到端验证：pack --key 签名 → verify --package 验签通过（含篡改拦截）。

**已知限制**：
- `publish` 依赖真实商店 API（`https://plugins.qomicex.top/api/v1`），设备流代码已对接验证（device code 请求 + token 轮询返回 pending 均正确），完整端到端需商店在线。
- `dev` v1 仅输出配置产物，不自动挂载到启动器（配合任务⑥ harness）。
- 长循环告警为文本启发式（非真 AST），可能误报/漏报。
