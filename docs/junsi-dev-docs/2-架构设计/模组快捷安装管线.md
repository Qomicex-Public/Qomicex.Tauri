# 模组快捷安装管线（下载中心后台化）

## 触发入口

资源中心 → 模组详情 → 「安装」对话框（`src/components/ResourceInstallDialog.tsx`）。
选择实例与版本后点击「开始安装」：解析并启动下载会话，**成功后立即关闭对话框并跳转 `/downloads`**，
进度由下载中心呈现（与整合包安装 ModpackInstallDialog 同模式）。

## 核心模块：`src/lib/quickInstall.ts`

`quickInstallViaDownloadCenter(opts)` 实现全部逻辑，对话框仅收集参数 → await → 跳转。

### 行为

1. **同步清理**：`toDelete`（版本切换需替换的旧文件）fire-and-forget 删除。
2. **创建 batch 任务**：任务名「安装: {资源名}」（i18n `downloads.quickInstallName`），type=batch，
   携带 steps（`downloads.steps.*` 渲染）：
   - 有前置依赖：`[download-deps, download-main]` 两步
   - 无前置依赖：仅 `[download-main]` 一步
3. **并行启动**：`Promise.allSettled` 并发启动全部前置 + 本体（`startResourceDownload`）。
4. **失败语义**：任一会话启动失败 → 取消已启动会话 + batch 任务标 failed + reject，
   对话框留在原处显示错误（可重试）。启动成功才 resolve 返回 batchId。
5. **后台聚合**（`aggregate`）：并行 `waitForCompletion` 轮询所有子会话，驱动：
   - 各 step 的 `percent`（组内平均进度）
   - batch 总进度（每文件均分）
   - step 终态（组内全部 completed → done；任一失败 → failed）
   - batch 终态（全部成功 → completed + `cacheInvalidate(api-instance-{id}-mods)`；否则 failed）
   聚合不依赖对话框组件存活（downloadStore 为模块级）。

## 下载中心适配

- `DownloadCenter.tsx` SSE 循环：`task.type === 'batch'` 的任务**跳过 install 会话 stale 检查**
  （`if (task.instanceId && task.type !== 'batch')`），避免 batch 任务的 instanceId 被误判为
  实例安装任务而标 failed（`taskExpired`）。
- batch 任务取消走 `cancelBatch(batchTaskIds)`（既有逻辑）。

## i18n

qomicex-tauri-i18n submodule `downloads.ts` ×7 语言新增：
- `steps['download-deps']` / `steps['download-main']`（前置资源 / 资源本体）
- `quickInstallName`（「安装: {name}」）

## 与模组更新路径的差异

- 模组更新 `updateModsViaDownloadCenter`（`src/lib/updateMods.ts`）：逐文件独立任务，完成后删旧文件。
- 快捷安装 `quickInstallViaDownloadCenter`：单 batch 任务聚合，2-step 并行。

### 2026-10-12 更新
## 依赖（前置）的处置口径

计划由 `src/lib/dependencyInstallPlan.ts` 的 `planDependencyInstall()` 生成，返回
`{ downloads, deletions }`：

- **已安装的前置（按远程 `projectId` 认定）：既不重下、也不删除。**
- 未安装的前置进入 `downloads`（URL/文件名优先取用户在依赖版本选择器里的覆盖，其次取上游解析值）。
- 无下载 URL 的依赖跳过，不伪造下载任务。
- **`deletions` 对依赖恒为空**：本地落盘名经命名模板（ENH-10）重命名，与依赖条目里的
  上游原名分属两个命名域，不能用来判定「过期」。要判定过期只能比对远程版本 id
  （`modrinthVersionId` / `curseForgeFileId`），属于版本切换功能的职责。

> issue #249 的根因正是误用文件名比较：`existing.fileName !== dep.fileName` 在两个命名域下
> 恒为 true → 已安装的前置被无条件列入删除，同时下载分支被 `continue` 跳过，表现为
> 「已存在的前置被删光且不补下载」。修复与取舍见 [ADR-112](../1-决策记录/ADR-112-快捷安装前置计划抽为纯函数并停止误删已安装前置-issue-249.md)。
> 该契约由 `pnpm run test:dependency-install-plan` 守住（CI `frontend-lint` 作业已接入）。
