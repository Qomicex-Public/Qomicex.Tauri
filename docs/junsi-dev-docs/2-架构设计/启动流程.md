# 启动流程

## 概述

Qomicex Launcher 的启动流程由前端 `RunningContext` 发起，经后端 `InstanceEndpoints` 编排流水线，最终由 Core.AOT 的 `LaunchExecutor` 创建 Minecraft Java 进程。进度通过 HTTP 轮询（非 SSE）实时反馈，崩溃自动触发诊断分析。

## 首次启动初始化向导（2026-08-15 新增）

全新安装（`{BaseDir}/QML/settings.json` 不存在）时，后端 `GET /api/settings` 返回 `initialized: false`，前端在 SplashScreen 就绪后显示**全屏初始化向导**（`src/components/InitialSetupWizard.tsx`，z-index 9998，无关闭/跳过按钮），强制完成后再进入主界面。详见 [ADR-017-首次启动初始化向导-快速-自定义双模式](../1-决策记录/ADR-017-首次启动初始化向导-快速-自定义双模式.md)。

```
SplashScreen(后端就绪)
  → GET /api/settings → initialized === true ? 主界面 : 向导
  → 向导：模式选择(快速/自定义)
      ├─ 快速(6步)：语言 → 主题 → Java → 内存 → 完成
      └─ 自定义(9步)：语言 → 主题 → 数据目录 → 游戏目录 → 下载源(测速) → Java → 内存 → 完成
  → PUT /api/settings（initialized: true）→ 主界面
```

- **Java 强制项**：两种模式均深度扫描（`scanRuntimes('deep')`），要求 Java 8/17/21 齐全；缺失版本在向导内联下载（`getJavaDownloadCatalog` → `startJavaDownload` → 轮询 `getJavaDownloadProgress` → `refreshCustomRuntimes`）。
- **兼容**：老用户升级（settings.json 存在但无 `initialized` 字段）时后端 `load_settings` 自动视为 `Some(true)`，不会重走向导。

```

  ├── [可选] Java 版本兼容性检查 → 用户取消则中止
  │
  ├── POST /api/instance/{id}/launch  →  LaunchResult
  │     │
  │     ├── success=false → CrashAnalysisDialog
  │     │
  │     └── success=true → 启动轮询
  │            │
  │            ▼
  │      ┌─ setInterval 500ms ────────────────────────┐
  │      │  GET /api/instance/{id}/launch/progress      │
  │      │  返回 LaunchProgress { stage, progress, ... }
  │      │       │
  │      │       ├── 'starting'~'launching' → 更新UI，继续500ms轮询

  │      │       │                             改为5s慢轮询（监控退出）

  │      │       │                             → 打开 CrashAnalysisDialog
  │      │       └── 'completed'            → 清除所有状态
  │      └─────────────────────────────────────────────┘
```

## 后端启动流水线（7阶段）

整个启动在 `InstanceEndpoints.cs`（第111-357行）中的 `Task.Run` 里异步执行，通过 `LaunchTracker` 实时更新进度供前端轮询。

| 阶段 | stage | 描述 |
|:---|:---|:---|
| 1 | `starting` | 许可证验证 |
| 2 | `resolving` | 认证解析（Microsoft / Yggdrasil / Offline） |
| 3 | `checking` | 完整性检查，对比缺失文件 |
| 4 | `repairing` | 下载缺失文件 |
| 5 | `preparing` | Java 运行时选择与环境准备 |
| 6 | `building` | 构建 LaunchOptions |
| 7 | `launching` | 调用 Core.AOT 创建游戏进程 |

### 阶段1：许可证验证

调用 `LicenseValidator.ValidateAsync()` 检查许可证文件是否存在且有效。

### 阶段2：认证解析

`ResolveAuthOptions()`（第519-568行）：

1. 获取默认账户 → 确定 `AuthMode`：`Microsoft` / `Yggdrasil` / `Offline`
2. Microsoft 账户自动调用 `RefreshLoginAsync()` 尝试刷新 token
3. 返回 `AuthOptions`：Name, Uuid, AccessToken, ServerUrl, AuthlibInjectorParam

### 阶段3：完整性检查

```csharp
if (!instance.SkipIntegrityCheck) {
    var missFiles = await repairCore.Locator.GetMissFilesAsync(jsonContent);
    // 去重、路径重映射
}
```

### 阶段4：文件修复

使用 `Qomicex.Downloader.Refactor.Downloader` 并发下载缺失文件，通过 IProgress 实时报告进度。

### 阶段5：Java 运行时选择

1. **检测所需 Java 版本**：从版本 JSON 读取 `javaVersion.majorVersion`，默认8
2. **选择**：用户指定 > `JavaRuntimeStore.GetMergedAsync(Quick)` → `JavaProvider.Recommand()` 推荐最匹配版本

### 阶段6：构建 LaunchOptions

```csharp
var launchOptions = new LaunchOptions {
    Version, VersionIsolation, GameRoot, JoinServer, JoinWorld,
    JavaOptions = { JavaPath, MaxMemoryMB, ExtraJvmArgs },
    AuthOptions = authOptions
};
```

### 阶段7：执行启动

```csharp
var result = await core.Launch.LaunchAsync(launchOptions);
```

## 核心启动引擎：LaunchExecutor

**文件：** `Core.AOT/Services/LaunchExecutor.cs`

```csharp
public interface ILaunchExecutor {
    Task<LaunchResult> LaunchAsync(LaunchOptions options);
    Task<bool> KillAsync(int processId);
}
```

实际 `LaunchAsync` 执行步骤：

1. **加载版本元数据**：读取 `versions/{version}/{version}.json`
2. **解压 Natives**：遍历 native 类库，解压到 `versions/{version}/{version}-natives/`
3. **拼接参数**：
   - JVM 参数（`-XX:+UseG1GC`, `-Dfml.*` 等 + 用户自定义）
   - MainClass（支持 InheritsFrom 继承链）
   - Game 参数（支持 `--server`/`--port` 和 `--quickPlayMultiplayer`/`--quickPlaySingleplayer`）
   - 参数变量替换（约20个，如 `${auth_player_name}`, `${classpath}`, `${natives_directory}`）
4. **创建进程**：

```csharp
var process = new Process {
    StartInfo = {
        FileName = javaPath,
        Arguments = paramsStr,
        UseShellExecute = false,
        RedirectStandardOutput = true,
        RedirectStandardError = true,
        WorkingDirectory = versionIsolation ? "versions/{version}/" : gameRoot
    }
};
process.Start();
```

5. **返回 LaunchResult**：Success, ProcessId, OnOutput, OnError, OnExit 回调

## LaunchTracker：进程监控器

**文件：** `Services/LaunchTracker.cs`

三个 `ConcurrentDictionary`：

| 字典 | Key | Value | 用途 |
|:---|:---|:---|:---|
| `_states` | instanceId | `ProcessState` | 追踪进程运行状态 |
| `_progress` | instanceId | `LaunchProgressState` | 存储启动阶段进度 |
| `_cts` | instanceId | `CancellationTokenSource` | 支持取消启动 |

核心方法：`Track()`, `GetState()`, `Stop()`, `SetProgress()`, `GetProgress()`

`LaunchProgressState` 字段：Stage, Message, Progress, Error, CurrentFile, TotalFiles, MissingFiles, ProcessId, IsRunning

## 前端启动组件

### RunningContext (`src/contexts/RunningContext.tsx`)

**职责**：集中管理启动状态、轮询、崩溃处理

**接口**：

```typescript
interface RunningContextValue {
  runningInstances: RunningInstance[]
  launchProgress: LaunchProgress | null
  launchingInstanceId: string | null
  launchInstance: (id, name, javaInfo?, quickJoin?) => Promise<LaunchResult>
  cancelLaunch: (id?) => Promise<void>
  killInstance: (id) => Promise<void>
  crashDialogState: CrashDialogState | null
  clearCrashDialog: () => void
  showLaunchError: (title, message, detail?, args?) => void
}
```

### 三个启动入口

| 页面 | 文件 | 触发方式 |
|:---|:---|:---|
| Dashboard | `src/pages/Dashboard.tsx` | "启动"按钮 → `handleLaunch()` |
| 实例列表 | `src/pages/Instances.tsx` | 卡片播放按钮 → 自动创建实例 → `ctxLaunchInstance()` |
| 实例详情 | `src/pages/InstanceDetail.tsx` | 普通启动 / 快速加入（joinServer/joinWorld） |

### LaunchProgressDialog (`src/components/LaunchProgressDialog.tsx`)

全局覆盖层（渲染在 `<Routes>` 之外）。

**UI 状态**：

| 条件 | 视觉表现 |
|:---|:---|
| 正常进行中 | 标题"启动游戏"，蓝色进度条，旋转加载图标 |
| crashed/failed | 标题变"启动失败"，红色进度条，显示错误信息 + crashReport |
| completed | "关闭"按钮 |

### CrashAnalysisDialog (`src/components/CrashAnalysisDialog.tsx`)

崩溃时自动触发崩溃分析流程：
1. 轮询到 `stage === 'crashed'/'failed'` → 设置 CrashDialogState
2. 自动调用 `POST /api/loganalysis/analyze-crash/{instanceId}`
3. 展示分析结果：错误信息、崩溃报告、mclo.gs 链接二维码、诊断报告导出

## 进度机制：轮询 vs SSE

| 场景 | 机制 | 端点 |
|:---|:---|:---|
| **启动进度** | HTTP 轮询（500ms/5s） | `GET /api/instance/{id}/launch/progress` |
| **下载/安装进度** | SSE 流 | `GET /api/progress/stream` |

启动使用轮询而非 SSE，因为启动生命周期短且需要精确的阶段状态切换。
