# 账号管理流程

## 概述

Qomicex Launcher 支持四种账号类型：**离线**、**Microsoft**、**统一通行证**、**Yggdrasil（外置登录）**。账号信息以 JSON 文件持久化在 `{DataDir}/QML/accounts/` 目录下。

## 页面与路由

| 页面 | 路由 | 组件 |
|:---|:---|:---|
| 账号列表 | `/accounts` | `Accounts` (`src/pages/Accounts.tsx`) |
| 账号详情 | `/accounts/:uuid` | `AccountDetail` (`src/pages/AccountDetail.tsx`) |

## 账号模型

```json
{
  "uuid": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "name": "玩家名",
  "type": "microsoft" | "offline" | "yggdrasil" | "tongyi",
  "accessToken": "...",
  "serverUrl": "https://...",
  "lastRefreshed": "2026-01-01T00:00:00Z"
}
```

## 账号类型对比

| 类型 | 认证方式 | Token 刷新 | 适用场景 |
|:---|:---|:---|:---|
| Offline | 本地生成 | 不需要 | 离线模式/内网 |
| Microsoft | OAuth 设备码 | 自动刷新 | 正版 Minecraft |
| Yggdrasil | 第三方认证 | 手动刷新 | 外置登录（统一通行证等） |
| TongYi | 统一通行证 API | 手动刷新 | 特定第三方认证 |

## 添加账号流程

### Microsoft 账号

```
点击"添加 Microsoft 账号"
  │
  ▼
POST /api/auth/microsoft/device-code  → 返回 device_code + user_code + verification_uri
  │
  ▼
弹出对话框：显示 user_code + verification_uri（可打开浏览器）
  │
  ▼
轮询 POST /api/auth/microsoft/poll（每5秒）
  ├── pending → 继续轮询
  ├── approved → POST /api/auth/microsoft/info（保存档案）
  └── expired → 提示超时
  │
  ▼
POST /api/account 保存账号 → 设为默认
```

### 离线账号

```
输入玩家名
  │
  ▼
POST /api/auth/offline  → 返回离线账号信息
  │
  ▼
POST /api/account 保存
```

### Yggdrasil（外置登录）

```
输入认证服务器 URL + 邮箱 + 密码
  │
  ▼
GET /api/account/yggdrasil-meta?serverUrl={url}  → 获取服务器元信息
  │
  ▼
POST /api/auth/yggdrasil  → 返回角色列表
  │
  ▼
POST /api/auth/yggdrasil/select  → 选择角色并保存
```

### 统一通行证

```
输入账号 + 密码
  │
  ▼
POST /api/auth/tongyi  → 返回账号信息
```

## Token 管理

| 操作 | 端点 |
|:---|:---|
| 验证 Token | `POST /api/auth/validate` |
| 作废 Token | `POST /api/auth/invalidate` |
| 刷新 Microsoft Token | `POST /api/auth/microsoft/refresh` |
| 检查丢失账号 | `GET /api/account/lost` |

## Token 自动刷新机制

- **Microsoft 账号**：启动游戏前自动调用 `POST /api/auth/microsoft/refresh`
- **其他账号**：需用户手动刷新
- 前端 `RunningContext.launchInstance()` 中调用 `resolveAccountCheck()` 确保账号有效

## 账号切换与默认账号

```
GET  /api/account                    → 列出所有账号
GET  /api/account/default           → 获取默认账号
PUT  /api/account/{uuid}/default    → 设置默认
DELETE /api/account/default          → 清除默认
```

- 启动游戏时自动使用默认账号
- Dashboard 显示默认账号头像和名称
- 无默认账号时弹出 `NoAccountDialog`

## 皮肤系统

与账号关联的皮肤操作：

| 操作 | 端点 |
|:---|:---|
| 获取皮肤档案 | `GET /api/skin/profile/{uuid}` |
| 获取皮肤图片 | `GET /api/skin/texture/{uuid}` |
| 上传皮肤 | `POST /api/skin/upload/{uuid}` |
| 重置默认 | `DELETE /api/skin/upload/{uuid}` |

- `AccountDetail` 页面使用 `SkinViewer3D`（基于 skinview3d）展示 3D 皮肤模型
- 头像通过 `AccountAvatar` 组件显示
- 支持本地皮肤覆盖上传

## Yggdrasil ALI 解析与 DnD 拖拽（2026-08-16 新增）

Yggdrasil 外置登录的验证服务器设置支持 authlib-injector 规范的两项能力：

### ALI（API 地址指示）

用户可在"自定义服务器地址"输入**缩略地址**（如 `littleskin.cn`）。输入框**失焦**时前端调用
`POST /api/account/yggdrasil-resolve` 解析：

- 解析成功且地址变化 → 输入框下方展示 `API 地址：{apiRoot}`，登录/保存账户均使用解析后的 API 根（规范要求启动器存储 API 根地址）；
- 解析结果 `insecure=true`（明文 http）→ 显示醒目警告"密码将以明文传输"；
- 解析失败 → 展示"无法连接该地址，将按原地址尝试"，登录回退使用原始输入。

```
输入缩略地址 → 失焦 → POST /account/yggdrasil-resolve → 展示 API 根 / 明文警告
                                                            │
                           登录（POST /auth/yggdrasil）使用解析后的 API 根
```

### DnD（拖拽添加验证服务器）

Yggdrasil 表单顶部有虚线 drop zone（整个表单容器亦响应）。拖动数据 MIME 为 `text/plain`，格式：

```
authlib-injector:yggdrasil-server:{URI 编码的 API 地址}
```

- 解析出前缀后的地址 → 弹确认框（"是否添加此验证服务器？{url}"）；
- 确认后填入服务器地址输入框，并自动触发一次 ALI 解析以展示解析/警告信息；
- 非 `authlib-injector:yggdrasil-server:` 前缀的内容被静默忽略。

### 时序变化

原 Yggdrasil 流程为 `输入 URL → meta → 登录 → 选角色`；现在 `meta` 前增加 ALI 解析步骤（仅自定义地址输入时触发，预设按钮直接使用完整 API 根、不解析）。`POST /api/auth/yggdrasil` 与 `yggdrasil/select` 端点本体不变。
