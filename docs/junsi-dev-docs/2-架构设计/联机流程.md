# 联机流程（Connector）

## 概述

Qomicex Launcher 的联机系统基于 **EasyTier**（P2P VPN）构建虚拟局域网，在此之上运行 **Scaffolding 协议**来管理房间和玩家。核心思路：用 EasyTier 将房主和房客置于同一虚拟子网，然后通过端口转发让房客连接到房主的 Minecraft 服务器。

## 架构总览

| 层 | 位置 | 职责 |
|:---|:---|:---|
| API 端点层 | `Endpoints/ConnectorEndpoints.cs` | 暴露 9 个 REST 端点 |
| 服务编排层 | `Services/Connector/ConnectorService.cs` | 协调子组件，管理会话生命周期 |
| Scaffolding 核心库 | `Qomicex.Connector/` | 房间创建/加入、协议通信、EasyTier 管理 |

## 网络拓扑

```
 ┌─────────────┐        ┌─────────────┐
 │   房主       │        │   房客 A     │
 │ 10.144.144.1 │        │  DHCP 分配   │
 │ MC:25565     │◄──────►│              │
 │ Center:xxxxx │  EasyTier P2P/Relay  │
 └─────────────┘        └─────────────┘
       │                       │
       │     ┌───────────┐     │
       └─────┤ 中继节点   ├─────┘
             │ (可选回退) │
             └───────────┘
```

## 房主创建房间

### 模式A：已知端口（`POST /api/connector/host/port`）

```
用户输入端口 / 系统自动扫描端口
  │
  ▼
GameProcessInspector.Inspect(port)
  ├── FindPidByPort(port) → PID
  ├── GetCommandLine(pid) → 启动参数
  └── 提取 --username, --uuid, --userType, --version
  │
  ▼
RoomCode.Generate() → "U/XXXX-XXXX-XXXX-XXXX"
  │
  ▼
启动 ScaffoldingCenter（在空闲 TCP 端口上）
  │
  ▼
启动 EasyTier 进程
  配置：--ipv4 10.144.144.1
       --network-name scaffolding-mc-{房间码前8位}
       --network-secret {房间码后8位}
       --tcp-whitelist={Center端口},{MC端口}
  │
  ▼
返回房间码给房客
```

### 模式B：选实例启动（`POST /api/connector/host/instance`）

自动启动游戏 + 自动发现端口：

1. 调用 `/api/instance/{id}/launch` 启动实例
2. 循环等待（最长5分钟，每2秒检测）：
   - **LAN 广播检测**：`LanGameListenerService` 监听 `224.0.2.60:4445` 组播
   - **TCP 端口扫描**：`GameProcessInspector.ScanAllJavaPorts()`
3. 发现新端口 → 进入模式A流程

## 房客加入房间（`POST /api/connector/join`）

```
输入房间码
  │
  ▼
RoomCode.Parse(code)
  │
  ▼
创建 ScaffoldingGuest
  │
  ▼
启动 EasyTier（房客配置：--no-tun --use-smoltcp --dhcp）
加入同一网络（--network-name / --network-secret）
  │
  ▼
CenterDiscoveryService.DiscoverAsync()
  在 EasyTier 网络中查找 hostname 匹配 ^scaffolding-mc-server-(\d+)$ 的节点
  最多等待30秒（每0.5秒扫描）
  │
  ├── 直连模式（优先）：TCP 连接 Center 虚拟IP:端口
  └── 端口转发模式（回退）：--port-forward tcp://127.0.0.1:{本地}/{中心IP}:{中心端口}
  │
  ▼
通过 c:server_port 协议获取 Minecraft 端口
通过 MapMinecraftPortAsync 映射端口到本机
  │
  ▼
返回 (mcHost, mcPort) → 前端写入 Minecraft 多人游戏地址
```

## Scaffolding 协议

在 TCP 上运行的二进制协议框架。

### 帧格式

```
┌──────────────────┬────────────────┬──────────┬──────────┐
│ body_len (4B BE) │ namespace(str) │ type(str)│   body   │
└──────────────────┴────────────────┴──────────┴──────────┘
```

### 标准协议（`c:` 命名空间）

| 协议键 | 用途 | 方向 |
|:---|:---|:---|
| `c:ping` | 心跳检测 | 双向 |
| `c:protocols` | 协议协商 | Guest→Center |
| `c:server_port` | 获取 MC 端口 | Guest→Center |
| `c:player_ping` | 玩家心跳（含名称、MachineId、EasyTierId） | Guest→Center |
| `c:player_profiles_list` | 获取在线玩家列表 | Guest→Center |

### QML 扩展协议（`qml:` 命名空间）

| 协议键 | 用途 | 方向 |
|:---|:---|:---|
| `qml:game_info` | 交换游戏版本信息 | Guest→Center |
| `qml:player_icons` | 交换玩家头像（Base64 PNG） | 双向 |
| `qml:player_leave` | 优雅退出通知 | Guest→Center |

### 心跳机制

每 **5 秒**发送一次 `c:player_ping`，连续失败触发 `ConnectionLost` → 自动调用 `LeaveAsync()`。

## EasyTier 配置详解

| 配置项 | 房主（Center） | 房客（Guest） |
|:---|:---|:---|
| `--ipv4` | `10.144.144.1`（固定） | 不设（DHCP） |
| `--no-tun` | 否 | 是 |
| `--use-smoltcp` | 否 | 是（用户态网络栈） |
| `--dhcp` | 否 | 是 |
| `--tcp-whitelist` | Center端口 + MC端口 | 无 |
| `--port-forward` | 无 | 远端端口映射到 127.0.0.1 |

### 关键技术点

- **P2P 打洞**：房客最多重试 **10 次**（间隔2秒）
- **端口转发回退**：房客无 TUN 设备权限时回退到 `--port-forward`
- **中继节点**：P2P 打洞失败时流量通过中继转发

## EasyTier 下载管理

**文件：** `Services/Connector/EasyTierProvider.cs`

- **版本**：v2.6.4
- **安装路径**：`{AppPaths.BaseDir}/QML/EasyTier/`
- **状态流转**：`idle → resolving → downloading → extracting → installed`（失败则 `failed`）
- **镜像测速**：并发探测 6 个代理前缀，选最快的
- **平台支持**：Windows / macOS / Linux（x86_64 / aarch64 / i686）

## GameProcessInspector

从 TCP 端口反查 Minecraft 进程信息，不直接挂钩进程，仅通过 OS API 读取进程元数据。

| 步骤 | Windows | Linux | macOS |
|:---|:---|:---|:---|
| 端口→PID | `GetExtendedTcpTable` (P/Invoke) | 读 `/proc/net/tcp` + inode 反查 | `lsof` |
| PID→命令行 | WMI / `wmic` / PowerShell | 读 `/proc/{pid}/cmdline` | `ps -p` |
| 参数解析 | 提取 `--username`, `--uuid`, `--userType`, `--version` | 同 | 同 |

---

## LanGameListenerService

监听 Minecraft 的 **LAN 广播**（Minecraft"对局域网开放"时发送）。

- **组播地址**：`224.0.2.60:4445`
- **协议**：UDP
- **消息格式**：`[MOTD]服务器名称[/MOTD][AD]端口号[/AD]`
- **条目存活期**：30秒无更新自动清理

在"选实例启动"模式中，用户需在游戏内点击"对局域网开放"→ 系统收到广播 → 自动触发创建房间。

## 房间码格式

`RoomCode.Generate()` 生成格式：`U/XXXX-XXXX-XXXX-XXXX`

- base-34 编码，含校验和
- 前8位作为 EasyTier 网络名，后8位作为网络密钥
- 校验和防止输入错误

## NAT 类型检测

`NatTypeDetector` 使用 STUN 协议检测：

| 结果 | 含义 |
|:---|:---|
| `cone` | 全锥形 NAT，P2P 成功率高 |
| `symmetric` | 对称 NAT，打洞困难 |
| `blocked` | UDP 阻断 |
| `unknown` | 仅测通一个服务器 |

前端 Badge：宽松（cone）/ 严格（symmetric，destructive 红色）

## 前端联机页面（`src/pages/Connect.tsx`）

**UI 结构**：

- **顶部**：NAT 类型 Badge + "NAT 检测"按钮
- **EasyTier 下载卡片**：进度条、速度、状态、失败重试
- **空闲状态**：
  - 创建房间 Tab：选实例启动 / 扫描端口 / 手动输入端口
  - 加入房间 Tab：输入房间码 `U/XXXX-XXXX-XXXX-XXXX`
- **房主视图**：房间码（可复制）+ 玩家列表 + 关闭按钮
- **房客视图**：服务器地址 `host:port`（可复制）+ 版本信息 + 玩家列表 + 退出按钮

**轮询**：`status.mode !== 'idle'` 时每2秒轮询 `/api/connector/status`
