# 技术选型

## 概述

Qomicex Launcher 是 Minecraft 游戏启动器，采用前后端分离 + 桌面外壳的三层架构。

## 关键决策

- **Axum 路由组装**: 使用 `Router::nest("/api", ...)` 组装各 endpoint 模块（`endpoints/*.rs`），对应旧 C# 版 `MapXxxEndpoints` 系列
- **已移除 NativeAOT / .NET**：后端重写为 Rust 后不再有 .NET 运行时与 NuGet 依赖；旧 C# 实现（`Qomicex.Launcher.Backend.Neo`、`Qomicex.Core.AOT` 等）仅存在于 `legacy` 分支
- **文件系统持久化**: 无数据库，所有状态存储在 `{DataDir}/QML/` 下的 JSON 文件中
- **SSE 进度流**: 使用 Server-Sent Events (`/progress/stream`) 统一推送进度更新
- **版本身份隔离**: 实例级 mods/saves/resourcepacks 隔离，通过 `versions/{inst.Name}/` 目录实现
- **Vite 代理**: 开发时 `/api/*` 代理到 `localhost:5000` 后端

## 关键决策

- **Axum 而非框架**: 使用 `Router::nest("/api", ...)` 组装各 endpoint 模块（`endpoints/*.rs`），对应 C# 版 `MapXxxEndpoints` 系列
- **Rust 主后端**: 自 ADR-004 起后端以 Rust (qomicex-backend) 为主，旧 C# 后端 `Qomicex.Launcher.Backend.Neo` 保留在 `legacy` 分支
- **文件系统持久化**: 无数据库，所有状态存储在 `{DataDir}/QML/` 下的 JSON 文件中
- **SSE 进度流**: 使用 Server-Sent Events (`/progress/stream`) 统一推送进度更新
- **版本身份隔离**: 实例级 mods/saves/resourcepacks 隔离，通过 `versions/{inst.Name}/` 目录实现
- **Vite 代理**: 开发时 `/api/*` 代理到 `localhost:5000` 后端
- **CORS**: `CorsLayer::permissive()`，开发环境任意来源
- **QIPC 管道传输（2026-08-22, ADR-040）**: release 模式下前端↔后端通信走 OS 管道（Windows Named Pipe / Unix UDS）+ Tauri `qomicex://` 自定义协议转发，TCP `:5000` 仅保留给 dev/CI（`QOMICEX_NO_TCP=1` 关闭）。后端 axum 路由零改动（`Router::call` 直入），流式端点经 `invoke('ipc_stream') + Channel` 消费。前端 `API_BASE` 为 ESM 活绑定；传输探测为**端到端校验**（fetch 协议 URL 的 `/ping` 断言 `pong`，双候选形态都试）且**随健康轮询每轮重试**——release 下后端解压/spawn 可能晚于首帧，一次性探测会永久锁错传输；探测失败自动回落 HTTP。动机是稳定性（端口占用不再致命）；插件系统 API 面不变。
