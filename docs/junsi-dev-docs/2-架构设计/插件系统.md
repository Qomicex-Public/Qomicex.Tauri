# 插件系统架构

## 概述

插件系统支持在启动器中加载第三方功能模块。插件以 `.qplugin` (zip) 包分发，包含 `manifest.json` 元数据和前端资源文件。

---

## 目录结构

```
plugins-dev/              ← 插件开发目录（开发用）
  com.example.plugin/
    manifest.json          ← 插件清单
    dist/                  ← 前端资源
      index.html           ← 插件页面内容（入口）
      overlay.html         ← 悬浮窗内容（可选）
      theme.css            ← 主题样式（可选）
  *.qplugin                ← 打包后的插件文件

plugins/                  ← 运行时插件目录（后端管理）
  com.example.plugin/
    manifest.json
    dist/...
```

---

## 插件生命周期

```
upload → installed → activatePlugin() → active → deactivatePlugin() → disabled
                           ↓                            ↑
                      renderInline()               destroy()
                      registerSlot()               unregisterPluginSlots()
                      setPluginState('active')     setPluginState('disabled')
```

- **installed**: 插件文件已解压，后端返回 `{ state: 'installed' }`
- **active**: 已激活，前端调用了 `activatePlugin()`，占位 `renderInline()` 创建了 DOM 容器
- **disabled**: 已停用，DOM 容器和 slot 已清理

激活/停用入口：`src/plugins/plugin-loader.tsx:9`（`activatePlugin`）和 `:49`（`deactivatePlugin`）。

## Plugin Manifest (`manifest.json`)

```json
{
  "id": "com.qomicex.example",
  "name": "示例插件",
  "version": "1.0.0",
  "minLauncherVersion": "0.1.0",
  "layers": ["l0", "l1", "l2", "l3"],
  "permissions": ["ui:toast", "ui:sub_window"],
  "entry": {
    "frontend": "dist/index.html",
    "theme": "dist/theme.css"
  },
  "contributes": {
    "menuItems": [
      {
        "path": "/plugins/p/com.qomicex.example",
        "label": "示例插件",
        "icon": "E",
        "action": "page"
      }
    ],
    "overlay": {
      "file": "dist/overlay.html",
      "title": "示例悬浮窗",
      "width": 380,
      "height": 500
    }
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 全局唯一插件 ID（reverse domain） |
| `layers` | string[] | L3 插件不会自动激活，需用户在设置页手动启用并重启 |
| `entry.frontend` | string | 插件页面入口 HTML（必需） |
| `entry.theme` | string? | 插件主题 CSS 文件路径 |
| `contributes.menuItems[].action` | string? | `"page"`（默认，点击导航到插件页面）/ `"overlay"`（点击直接弹悬浮窗） |
| `contributes.overlay` | object? | `action: "overlay"` 时必需，指定悬浮窗内容文件和尺寸 |

### 类型定义（TypeScript）

- `src/plugins/types.ts`: `PluginManifest`, `PluginContributes`, `PluginMenuItem`, `PluginInfo`
- 后端 C# 映射: `src-backend/.../Models/PluginManifest.cs`

## 渲染模式

### Inline（默认）

插件页面内容以 `innerHTML` 注入到 `PluginPage` 组件的 `containerRef` 中，`<script>` 标签通过 `activateInlineScripts()` 克隆执行以绕过 `innerHTML` 脚本安全限制。

入口：`src/plugins/sandbox.ts:113` `renderInline()` → `src/pages/PluginPage.tsx:62` `activateInlineScripts()`

### Sandbox（iframe, 备选）

插件内容载入 `<iframe sandbox="allow-scripts">`，提供完整隔离。当前未启用。

入口：`src/plugins/sandbox.ts:70` `createSandbox()`

## 插件 API 桥接

### Inline 桥接

插件页面脚本通过 `window.__PLUGIN_API__` 对象与主程序通信：

```js
// 注入位置：sandbox.ts:160-178 的 <script> 标签
window.__PLUGIN_API__ = {
  call: (method, ...args) => {
    // 返回 Promise，内部通过 window.postMessage 与主程序通信
  }
}
```

### Sandbox 桥接

iframe 内脚本通过 `parent.postMessage` 通信，主程序注入 `apiBridgeScript`（`sandbox.ts:35-68`）。

### 支持的 API 方法

| Method | 权限 | 说明 |
|--------|------|------|
| `getSettings` | `config:read` | 读取插件设置 |
| `setSettings` | `config:write` | 写入插件设置 |
| `callBackend` | `network:fetch` | 调用后端 API |
| `navigate` | `config:read` | 跳转页面 |
| `showToast` | `ui:toast` | 显示通知 |
| `overlay.create` | `ui:sub_window` | 创建悬浮窗 |
| `overlay.show` | `ui:sub_window` | 显示悬浮窗 |
| `overlay.hide` | `ui:sub_window` | 隐藏悬浮窗 |
| `overlay.destroy` | `ui:sub_window` | 销毁悬浮窗 |
| `overlay.setHtml` | `ui:sub_window` | 更新悬浮窗内容 |
| `overlay.setPosition` | `ui:sub_window` | 移动悬浮窗 |

权限列表：`src/plugins/sandbox.ts:211-216` `METHOD_PERMISSIONS`
API 实现：`src/plugins/plugin-api.ts` `createPluginBridge()` → 通过 `window.__pluginOverlayStore` 全局对象访问 store 方法

## 悬浮窗系统

### 创建流程

1. 插件调用 `__PLUGIN_API__.call('overlay.create', opts)`
2. → `sandbox.ts:232` `bridge.createOverlay(opts)` → `plugin-api.ts:49`
3. → `window.__pluginOverlayStore.createOverlay(pluginId, opts)` → `pluginStore.ts:74`
4. → 生成 overlay ID，追加到 `store.overlays` 数组
5. → `PluginOverlayManager.tsx` 监听 `overlays` 变化，渲染 `<Floater>` 组件
6. → 每个 Floater 创建一个 `<iframe sandbox="allow-scripts">`，SRC 为 blob URL（内容由 `overlayHtml()` 函数包装）

### 关闭/隐藏

- 关闭按钮 (`×`) → `destroyOverlay(id)` → 从 `overlays` 数组中移除
- 最小化按钮 (`—`) → `hideOverlay(id)` → 设置 `visible: false`，显示在底部 `MinimizedBar`

关键文件：`src/components/PluginOverlayManager.tsx`

## 侧边栏 Slot 系统

插件通过 `registerSlot()` 将自定义 UI 注入固定位置。

```ts
registerSlot(pluginId, 'sidebar:bottom', () => <NavItem to={...} />)
```

Slot 类型（`src/plugins/slots.tsx:3-8`）：
- `sidebar:bottom` — 侧边栏底部（当前唯一使用）

渲染位置：`src/components/PluginSidebarItems.tsx` → 由 `Sidebar.tsx` 调用

### Overlay 快捷方式

当 `menuItems[].action === "overlay"` 时，slot 注册 `OverlaySidebarButton`（`plugin-loader.tsx:76`）：
1. 点击按钮 → fetch `/api/plugins/{id}/files/{overlay.file}`
2. 获取的内容作为 overlay HTML → `store.createOverlay()`
3. 直接弹出悬浮窗，不导航到插件页面

## 启动进度钩子（plugin:launch-progress-override）

L3 插件可以通过 `CustomEvent` 自定义启动进度文案：

```js
window.addEventListener('plugin:launch-progress-override', (e) => {
  e.detail.message = '自定文案...'
})
```

分发位置：`src/components/LaunchProgressDialog.tsx`（每次渲染时 dispatch）
监听时机：插件页面加载后即可注册监听器

## PluginPage 渲染机制

### 路由

`/plugins/p/:pluginId` → `src/pages/PluginPage.tsx`

### 行为

1. PluginPage 使用 `containerRef` div 作为插件内容挂载点
2. `useLayoutEffect` 每 50ms 轮询 `getInstance(pluginId)` 直到就绪
3. 获取到实例后将 `inst.container` 移入 `containerRef`
4. 首次载入时调用 `activateInlineScripts(c)` 执行插件脚本
5. 切换插件时 `containerRef` 先清空 (`innerHTML = ''`)，再挂载新插件
6. 重复访问同一插件不会重复激活脚本（`c.dataset.scriptsActivated` 标记）

### 已知坑点

- 不支持同一插件页面多实例
- 脚本内的 `getElementById('root')` 被劫持为返回插件容器元素
