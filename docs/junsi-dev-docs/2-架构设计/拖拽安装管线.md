# 拖拽安装管线（文件拖入一键安装）

> 功能来源：Issue #20（拖拽整合包文件快速安装整合包）+ 扩展支持模组/光影包/资源包拖入。
> 设计决策：见 ADR「拖拽安装采用原生层事件链路而非 DOM 层」。

## 事件链路（关键）

**原生层（Tauri Rust）→ 前端全局组件**，不在 DOM 层做 HTML5 文件拖放：

- `src-tauri/src/lib.rs` 的 `setup` 里 `win.on_window_event` 监听 `tauri::WindowEvent::DragDrop`：
  - `Enter` → emit `file-drop-hover` (true)
  - `Leave` → emit `file-drop-hover` (false)
  - `Drop { paths }` → emit `file-drop-hover` (false) + `file-drop` (paths)
- 前端 `src/components/GlobalDropInstaller.tsx`（挂载于 `Layout.tsx`，与 `PluginEventBridge` 同层）：
  - `listen('file-drop-hover')` → 全屏虚线遮罩（`释放以安装` 提示）
  - `listen('file-drop')` → 逐路径 `classifyFile` → 同类分组 → 打开 `DropInstallDialog`

**为何不用 DOM 层**：Tauri v2 (wry) 在 Windows 上把**文件**拖放交给原生层接管，DOM 收不到文件 drop；而文本/URI 拖放仍走 DOM。因此 Yggdrasil 登录的服务器链接拖入（`Accounts.tsx` 的 `text/plain` DOM drop）与文件拖放天然隔离，互不影响。

`PluginEventBridge` 仍监听 `file-drop` 转发给 assistant 插件（`top.qomicex.assistant`），两个监听器并存，互不干扰。

## 文件分类

`POST /api/resource/classify-file`（`src-backend/qomicex-backend/src/endpoints/resource_download.rs`），body `{ path }`：

| 文件 | 判定 | 返回 |
|------|------|------|
| `.jar` / `.litemod` | 扩展名 | `mod` |
| `.mrpack` | 扩展名 + modrinth.index.json | `modpack` + name/gameVersion/loader/summary |
| `.zip` | 内容探测（优先级） | — |
| ↳ 含 qmodpack.index.json | 整合包 | `modpack` |
| ↳ 含 modrinth.index.json | 整合包 | `modpack` |
| ↳ 含 manifest.json 且 manifestType=minecraftModpack | CF 整合包 | `modpack` |
| ↳ 含 shaders/ 目录 | 光影包 | `shaderpack` |
| ↳ 含 pack.mcmeta | 资源包 | `resourcepack` |
| 其他 | — | `unknown` |

分类 zip 时跳过 `__MACOSX/` 条目；CF manifest 必须校验 `manifestType == "minecraftModpack"`，否则降级继续探测（普通 zip 里的 `manifest.json` 不能误判为整合包）。

## 安装分流

拖入文件分组后进入 `src/components/DropInstallDialog.tsx`：

### 资源类（mod / resourcepack / shaderpack）
- 展示文件列表 + 实例选择（复用 `ResourceInstallDialog` 的搜索+单选卡片模式，按 `settings.gameDir` 过滤、mod 类额外过滤 `loader` 非空）
- 确认 → 逐个 `POST /instance/{id}/files/import-local`（`src-backend/qomicex-backend/src/endpoints/instance_files.rs`）
- mod 安装后调用 `cacheInvalidate('api-instance-{id}-mods')` 失效模组缓存
- 结果 toast：全部成功 / 部分失败统计

### 整合包（modpack）
- 预览：packName（可编辑实例名）、gameVersion、loader、目标目录（settings.gameDir + 版本隔离开关）
- 确认 → `POST /modpack/install-direct`（`src/api/instance.ts` `installModpackDirect`），`id` 即实例名，`path` 直传本地绝对路径（后端 `parse_local_pack_file` 本地解析，不走 multipart 上传）
- 成功后 `addTask` 登记下载中心任务 + toast，不跳转下载中心

## 边界行为

- **多文件同类型**：批量安装到所选实例
- **混合类型**：toast 提示拆开拖入，不安装
- **不支持文件**（unknown）：toast 列出文件名，忽略
- **多整合包**：只装第一个，提示忽略其余
- **浏览器环境无 Tauri**：`listen()` 失败被 `.catch(() => {})` 静默，不影响其他功能

## 本地文件导入端点

`POST /instance/{id}/files/import-local`，body `{ category, sourcePath, fileName? }`：

- category 仅支持 `mods` / `resourcepacks` / `shaderpacks`（其他返回 400 `IMPORT_CATEGORY_INVALID`）
- 扩展名校验：mods → jar/litemod，其余 → zip（不符返回 400 `IMPORT_EXTENSION_MISMATCH`）
- 目标目录：版本隔离时 `{gameDir}/versions/{inst.Name}/{category}`，否则 `{gameDir}/{category}`（复用 `resolve` + `category_dir`）
- 重名自动 `name (1).ext` 后缀，不静默覆盖
- 源文件保留不删除

## 验证方式

- 接口：`scripts/test-api-filters.sh` 无覆盖；手测见调试记录（classify 7 用例 + import-local 正向/异常 4 用例全过）
- 前端链路：Playwright Tauri mock 注入（文档《前端浏览器调试-Playwright-Tauri-mock注入.md》），增强 mock 记录 `file-drop-hover` / `file-drop` listener，用 `__mockCbs` 手动触发事件模拟拖入，验证遮罩显示 → 分类 → 对话框打开
- 真实文件拖放需在 `pnpm tauri dev` 里人工验证（浏览器 mock 无法模拟原生文件 drop）
