# ADR-094：资源收藏 P2（#132）收藏夹分组 / 备注 / 自定义标签

- 状态：已接受
- 日期：2026-10-01
- 影响面：后端（新增 `services/resource_favorite_folder.rs`、`state.rs`、`endpoints/resource_center.rs`）、
  前端（`types/index.ts`、`api/resource.ts`、`stores/favoritesStore.ts`、新增
  `components/FavoriteEditDialog.tsx`、`pages/ResourceCenter.tsx`、`pages/ResourceDetail.tsx`）、
  i18n submodule（7 语言 `resource.favorites.{folders,note,tags,edit}`）
- 关联：ADR-091（P1 后端持久化 + 收藏视图）、Issue #132

## 背景

P1（ADR-091）已把「收藏 / 取消收藏 + 收藏视图」落地，并在 JSON 里预置了
`folderId` / `note` / `tags` 三个字段（`#[serde(default)]`），P1 的
`POST /api/resource-favorites`（upsert）已经会写入这三个字段。P2 要补的是：
**收藏夹实体**、**备注 / 标签的编辑入口**、**按收藏夹与标签筛选**。

用户确认的方案：收藏夹存独立文件、编辑用弹窗、左侧收藏夹栏 + 顶部标签 chips、
**删除收藏夹时连同夹内收藏一起删**。

## 决策

### 1. 收藏夹实体存独立文件（不对 P1 格式做迁移）

新增 `{BaseDir}/data/resource_favorite_folders.json`（`Vec<FavoriteFolder { id, name, createdAt }>`），
仿 `instance_group.rs`：`Mutex<Vec<_>>` + 原子写 + 错误上报 + 中毒锁恢复。
收藏项通过已有的 `folder_id` 关联。

舍弃单文件信封 `{version, folders, items}`：虽然「删夹子 + 清引用」能一次原子写，
但要对既有扁平数组做读写迁移并重写 P1 的 `load_from_file` / `save_locked` 与其测试，
代价大于收益。

### 2. 元数据编辑复用 P1 的 upsert，不新增 PATCH

`folderId` / `note` / `tags` 由 P1 已有的 `POST /api/resource-favorites` 写入；
P2 只新增收藏夹的 4 个端点：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/resource-favorite-folders` | 列表（插入序） |
| POST | `/api/resource-favorite-folders` | 新建；名称 trim 后非空、≤64 字符、大小写不敏感去重 |
| PUT | `/api/resource-favorite-folders/{id}` | 重命名 |
| DELETE | `/api/resource-favorite-folders/{id}` | 删除并**级联删除夹内收藏**，返回 `{removed, removedFavorites}` |

错误码沿用实例分组风格：`FAVORITE_FOLDER_NAME_EMPTY` / `_NAME_TOO_LONG` /
`_NAME_EXISTS`（400）、`FAVORITE_FOLDER_NOT_FOUND`（404）；落盘失败走
`ApiError::internal`（500 `INTERNAL_ERROR`，原因在 message）——与 P1 收藏端点同一口径。

舍弃新增 `PATCH /api/resource-favorites`：`note` 需要区分「不改」与「置空」，
会引入 `Option<Option<String>>` 或 `clearNote` 标志，复杂度不值得。

### 3. 删夹子的级联顺序：先删夹内收藏，再删夹子

`DELETE` 端点先 `ResourceFavoriteService::remove_by_folder(id)`（写 items），
再 `ResourceFavoriteFolderService::delete(id)`（写 folders）；且**先 `exists()` 判存在**，
对不存在的 id 直接 404、不做破坏性级联。

顺序理由：两步写不是原子的。若第二步失败，最坏是「收藏已删、夹子空着」这种无害残留；
反序则会留下指向已删夹子的悬空 `folderId`。前端另外把「folderId 指向不存在的夹子」
防御性显示为「未分组」。

> 删夹子是**破坏性且不可撤销**的，因此 `choose()` 确认框必须写出条数：
> 「「{name}」及其中的 {count} 个收藏都会被删除，此操作不可撤销。」

### 4. 校验与上限（落库边界统一执行）

- 键段：`normalize_key()`（P1）。
- P2 元数据：新增 `ResourceFavorite::normalize_meta()` 并在 `upsert` 内调用 ——
  `folderId` trim 后空串 → `None`；`note` trim 后空串 → `None`、超长按**字符**截断到 2000；
  `tags` 逐个 trim、丢空、**大小写不敏感去重**（保留首次出现的写法）、单标签截断到 32 字符、
  整体上限 20 个。
- 收藏夹名：trim 后非空、≤64 字符（按字符数而非字节数）、大小写不敏感去重。

上限刻意放在服务端（UI 只做提示）：本地 JSON 也不应无界增长。

### 5. 前端：两栏收藏视图 + 弹窗编辑

- 收藏视图改为 `lg:grid-cols-[212px_minmax(0,1fr)]`：左侧收藏夹栏
  （全部 / 未分组 / 各夹子 + 计数 + 新建 + 悬浮重命名/删除），右侧「标签 chips + 列表」。
  搜索视图不加包裹层，保持原单列布局。
- 标签 chips 从**当前来源/分类**的收藏里聚合（不受夹子/标签过滤影响，避免选项自己消失），
  按出现次数降序；多选即 AND 过滤。
- 编辑入口：卡片右下角 ✎ 与详情页的「编辑收藏」，共用一个 `FavoriteEditDialog`
  （收藏夹下拉 + 备注 textarea + 标签 chips 输入）。
- 收藏夹的新建/重命名用 `useMessageBox().prompt`，级联删除用 `choose`——不自建输入弹窗。
- **新建收藏夹后不切换过滤器**：新夹子必然为空，跳过去只会让用户面对空列表。
- `folderId` 指向不存在的夹子一律按「未分组」统计与展示。

### 6. store 的并发口径（在 P1 基础上扩展，不改变其不变量）

- `updateFavoriteMeta` 与 `toggleFavorite` **共用同一条按收藏键的串行队列**
  （`serializeByKey`）：改备注/夹子和加/删收藏都是同一条记录上的写操作，并发时同样会出现
  「后写的被先发的响应覆盖」。
- 收藏夹的增删改也计入 `mutationEpoch` / `inFlightMutations`，因此过期的
  `load()` / `loadFolders()` 响应一样会被丢弃并登记重拉（`pendingReload` 拆成
  `favorites` / `folders` 两个标记）。
- `deleteFolder` 在发请求前 **`await Promise.allSettled([...favoriteMutationTails.values()])`**：
  级联删除夹内收藏时若还有同键 POST 在飞，它可能在级联删除之后把条目重新加回来。
- P1 的不变量保持不变：按收藏键串行化、`load` 世代号 + 在飞 mutation 计数、只回滚当前键、
  强制重拉收敛。

## 已知限制

1. 收藏夹只有 `id` / `name` / `createdAt`，**无颜色/排序/嵌套**；夹子按插入序展示。
2. 删夹子不可撤销，且没有「回收站」。
3. 标签是每条收藏的自由文本，没有全局标签表；重命名标签需要逐条编辑。
4. 收藏夹与收藏都不做跨设备同步（本地 JSON）。
5. `install_service::tests::dedup_miss_files_normalizes_separators_before_comparing`
   是**既有 flake**（单独跑该模块 5 次可复现 3 次失败，与收藏代码无关：`dedup_key`
   依赖进程级大小写探测缓存 `OnceLock<Mutex<HashMap<PathBuf,bool>>>`）；本 PR 未处理。


### 2026-10-01 更新

## 修订（v1.1）：收藏视图布局改版 —— 去左栏、顶部工具行、全宽卡片

### 背景与触发

v1.0 的收藏视图是「左侧 212px 收藏夹栏 + 右侧列表」。UI 评审后按新设计图调整为
「顶部一行工具区 + 全宽卡片」，并明确要求「符合实际与用户体验要好」——因此对设计图里
两处不实际的地方做了取舍（见下）。

### 决策

1. **收藏夹选择从左侧常驻栏改为顶部下拉**（`Popover`，非 `Select`）：
   触发按钮显示「图标 + 当前范围名 + 计数 + ▾」；弹出层含「收藏夹」标题、
   全部 / 未分组 / 各夹子 + 计数、每项悬浮的 ✎ 重命名 / 🗑 删除，以及底部「新建收藏夹」。
   选任意一项后自动收起（`setFavFolderMenuOpen(false)`）。
   **因 `Select` 只支持 `value/label` 选项，塞不下增删改动作**，故用 `Popover`。
2. **视图切换只保留一个按钮，文案随视图变**：搜索视图显示绿色「♥ 收藏（N）」（进入收藏）；
   收藏视图显示「🔍 搜索」（点回搜索）。按钮带 `aria-pressed` 表达当前视图。
   *评审中曾同时实现「🔍/♡ 图标组」与「绿色收藏按钮」两套入口，语义冲突（在收藏视图里
   那个绿色按钮点下去是「返回搜索」，看起来却像「去收藏」），故合并为一套。*
   该按钮带可见文字，因此不再套 `Tooltip`（`Tooltip` 只用于纯图标按钮）。
3. **收藏视图新增本地搜索**（标题 / 作者 / 标签，大小写不敏感）：纯前端过滤，**不发网络请求**。
   复用既有 i18n 键 `resource.searchPlaceholder`（`'搜索{category}...'`）+ `favorites.viewLabel`
   渲染出「搜索收藏...」，因此本轮**零新增 i18n 键**。
   *该搜索框只在收藏视图渲染：搜索视图已有自己的一整行搜索区，若两处都渲染会出现两个搜索框
   （评审实测确认过该缺陷并修复）。*
4. **标签筛选保留 chips 行**（未改成设计图里的下拉 chip）：标签较少时一目了然、
   多选即 AND 一次点击可达；改成下拉会把一次多选变成多次开合。
5. **「共 N 个收藏」从列表底部移到筛选行右侧**（`ml-auto`），且仅在列表非空时显示
   （空列表由空态文案承担，避免重复）。
6. 后端、store、API、i18n **零改动**：夹子计数、过滤链路、并发口径全部复用 v1.0 实现。

### 舍弃方案

- 保留左侧收藏夹栏、只统一顶部工具行（改动最小，但左栏继续占 212px 宽度）。
- 完全照图并保留一个收藏视图里不生效的搜索框（点了没用的控件）。
- 标签筛选改为下拉 chip（多选需多次点击）。
- 把收藏夹下拉抽成独立组件文件（仅此一处使用，内联改动面更小、避免过度抽象）。

|---|---|
| `cargo test --bin qomicex-backend` | **299 passed / 0 failed / 2 ignored**（后端零改动，回归确认） |
| `pnpm run typecheck` / `pnpm run build` | 通过 / 通过 |
| `eslint`（改动文件） | 0 error（1 条既有 `t` 依赖 warning） |
| 浏览器实测（Playwright + mock） | 搜索视图**只有 1 个搜索框**（修复了重复框）；收藏视图出现夹子下拉（全部 2 / 未分组 1 / 优化 1 + 新建）与「搜索收藏…」；选「优化」→ 触发按钮变「优化 1」且列表只剩该夹条目；收藏内搜索 `mezz` 命中作者、`性能` 命中标签、无命中时显示空态；单一按钮在两种视图间来回切换正确（文本/`aria-pressed` 同步），URL 正确写入 `view=favorites` |



### 2026-10-02 更新

## 修订（v1.2）：顶部工具行收敛为单一「模式」切换

### 背景

v1.1 后仍有三个控件在表达「收藏」：模式图标按钮（🔍/♡）、右上角绿色「♥ 收藏 (N)」按钮、
以及收藏模式的复选入口。评审指出**「收藏」不应既是左侧下拉的内容、又在右上角单独出现**，
并要求整个资源中心只保留**一个核心切换**：资源浏览 ↔ 收藏浏览。

### 决策

1. **模式切换收敛为一个下拉，固定在最左**（位置与组件在两种模式下都不变）：
   - 触发按钮显示「图标 + 当前模式名 + ▾」（♥ 收藏 / ◇ 资源）；
   - 弹出层两项：♥ 收藏 / ◇ 资源，当前项高亮 + ✓，选完自动收起。
   **删除右上角绿色「♥ 收藏 (N)」按钮**（职责与模式下拉重复，且布局上悬空）。
2. **收藏范围作为收藏模式的第二个控件**（紧随模式下拉）：
   `📁 全部 1 ▾`（全部 / 未分组 / 各收藏夹 + 计数 + 悬浮重命名/删除 + 底部新建）。
   模式与范围职责分离：**最左永远是模式**，不会因为「范围」而让最左控件含义漂移。
3. **搜索框两模式共用同一位置**：
   - 收藏模式：`搜索收藏…`，**即时本地过滤**（标题/作者/标签），因此**不渲染「搜索」按钮**
     —— 即时过滤配一个按钮就是「点了没用」的控件；
   - 资源模式：`搜索资源、关键词…` + 「搜索」按钮（回车或点击触发后端检索）。
4. **资源模式原有的「搜索框 + 排序 + 搜索按钮」一行拆解**：搜索框与按钮上移到工具行，
   该行只保留**排序**下拉（`v1.1` 时同一位置已有搜索框，会重复，已移除）。
5. i18n：新增 `resource.mode.{label,browse,searchPlaceholder}` 与
   `resource.favorites.searchPlaceholder` 共 4 键（7 语言，单独 PR）；
   同时删除 v1.1 起就已零引用的死键 `resource.favorites.filterHint`。
   **保留** `favorites.viewSearch` / `viewLabelWithCount`（暂无引用但属既有键）。

### 最终形态

```
收藏模式：
[ ♥ 收藏 ▾ ] [ 📁 全部 1 ▾ ] [ 🔍 搜索收藏……              ]
        ↓
[ 资源源 ] [ 资源分类 ]
        ↓
[ 标签筛选 ]                                  [ 共 X 个收藏 ]

资源模式：
[ ◇ 资源 ▾ ] [ 🔍 搜索资源、关键词……        ] [ 搜索 ]
        ↓
[ 资源源 ] [ 资源分类 ]
        ↓
[ 排序 ▾ ] [ 游戏版本 ▾ ] [ 加载器 ▾ ]
```

### 舍弃方案

- 保留右上角绿色「收藏 (N)」按钮（职责重复 + 悬空）。
- 把「模式」与「收藏范围」合成一个下拉（一个菜单混两件事，用户难分辨"当前是模式还是范围"）。
- 模式改用两个图标按钮（需 Tooltip 注释，且与「一个核心切换」的目标不符）。
- 收藏模式也放「搜索」按钮（即时过滤下无实际行为）。
- 资源模式占位符写「搜索资源、作者、关键词…」：后端 `SearchQuery` 只有单个 `keyword`
  参数、直接转发上游，**「是否按作者匹配未经我验证**，故不写入该能力（不夸大）。

## 修订（v1.3）：分类聚合 + 卡片 hover 动作 + 顶部可折叠 + 搜索/收藏 Toggle

### 背景与触发

v1.2 之后评审提出一批 UX 改进：搜索/收藏改为右侧 Toggle、去掉左上「模式」下拉、
卡片动作改为 hover 滑入、去掉「原站」按钮、资源源「全部」改名「聚合」、
资源分类新增「聚合」（覆盖所有资源类型）、顶部筛选区可折叠且状态持久化。

### 2026-10-02 更新（第五次）

## 修订（v1.6）：筛选行合并——排序 / 游戏版本 / 加载器同一行

### 背景与触发

原先「排序」是**独立一行且没有标题**，「游戏版本」「加载器」在**另一行**、各有自己的
标题。用户要求：「将相关度之类的和游戏版本，加载器放到一行并且一样补齐头部的提示
『排序方式』」。

经 `ask_user_question` 确认两点：
1. 排序标题文案 → **「排序方式」**（与「游戏版本」「加载器」同为 4 字名词，命名风格统一）；
2. 「类别筛选」那些标签 → **保持在下一行独占**（标签数量多，挤进同一行会换行错位）。

### 决策

1. 把排序从独立的 `<div className="flex flex-wrap items-center gap-3">` 移入与
   「游戏版本」「加载器」同一个 `flex flex-wrap items-start gap-4` 容器，并补上标题
   `<p className="text-[11px] font-medium text-muted-foreground">{t('resource.sortLabel')}</p>`
   —— 与另两个标题**完全同一套 class**。
2. 排序控件高度由 `h-10` 改为 **`h-9`**，与 Combobox（内部 input 固定 `h-9`）和
   加载器的 Select 统一。三者标题 y 与控件 y 因此完全对齐。
3. 新增 i18n 顶层键 `sortLabel`（7 语言）：
   - zh-CN / zh-TW / zh-HK: `排序方式`
   - en-US / en-GB: `Sort by`
   - ja-JP: `並び順`
   - ru-RU: `Сортировка`
   **不复用 `sort.*` 子对象**——那是选项名（相关度/下载量…），与「标题」语义不同。
4. 「类别筛选」保持独占下一行不变（`tagsSupported` 判断也没动）。

### 最终形态

```
[ 排序方式 ]   [ 游戏版本 ]    [ 加载器 ]
[ 相关度 ▾ ]   [ 全部版本 ▾ ]  [ 全部加载器 ▾ ]   ← 三者同 y、同高 36px
[ 类别筛选 ...标签... ]                            ← 独占下一行
```
