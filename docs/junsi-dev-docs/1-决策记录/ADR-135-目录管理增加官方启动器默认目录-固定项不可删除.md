# ADR-135：目录管理增加官方启动器默认目录，固定项不可删除

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-18 |
| 决策者 | AI Agent |
| 关联 | issue #360、ADR-025（目录管理「当前目录」占位）、ADR-122（游戏目录搬迁） |

## 背景

issue #360：目录管理默认是空的，而实际默认游戏目录是一个看不出位置的 `.minecraft`。用户要求目录管理固定存在一个不可删除的默认目录：

- 官方启动器目录（Mojang 的 `.minecraft`）。

实测与代码事实：

- 目录管理（`src/pages/Instances.tsx`）只列 `localStorage['qomicex-directories']`，列表为空就是空态；`currentDir` 取 `settings.gameDir`，后端默认是 `$HOME/.minecraft`。
- 官方启动器的目录与 `$HOME/.minecraft` 不是同一个位置：Windows 是 `%APPDATA%\.minecraft`，macOS 是 `~/Library/Application Support/minecraft`，Linux 仍是 `~/.minecraft`。
- 曾考虑再加一个「启动器默认目录」（`{数据目录}/.minecraft`），但各平台对「启动器自己的游戏目录」没有统一约定（macOS 尤其容易与官方目录混淆），最终只保留官方目录，并把它作为新装默认值。

## 决策

1. 目录管理固定展示**官方启动器目录**：由后端按平台解析，经 `/systeminfo` 的 `officialGameDir` 暴露。
2. 固定项**并入 `qomicex-directories` 数组**并带 `fixed: 'official'` 标记，因此可以与用户目录混排、顺序随现有 `saveDirs` 持久化。加载时按当前系统路径校正、与普通目录按规范化路径去重（分隔符统一、Windows 忽略大小写）；旧版本残留的 `fixed: 'launcher'` 条目会被清掉。
3. 固定项**不可删除、不可重命名**（右键菜单与行内按钮都不提供），可设为当前、可打开、可上移/下移；名称取 i18n（`instances.officialDir`，中文为「官起目录」）。
4. 新装/设置重置的默认 `gameDir` 直接使用官方启动器目录（`SettingsResponse::default` 走 `default_game_dir()` → `official_game_dir()`）。已有用户保存过 `gameDir`，不受影响；已有实例各自的 `gameDir` 也不变。
5. 页内刷新会重新拉取 `/systeminfo`；失败时保留现有列表，下次刷新重试。

## 备选方案

### 同时增加「启动器默认目录（数据目录下 .minecraft）」
- 优点：游戏文件与启动器数据放在一起，便于整体搬走
- 缺点：各平台没有统一约定，macOS 上与官方目录语义冲突；固定项多一个、排序与去重状态更复杂
- 为何不选：不采纳：用户明确要求去掉，默认直接用官方目录

### 固定项固定在顶部，不参与排序
- 优点：实现最简单，不需要合并进持久化数组
- 缺点：用户要求「允许排序」，固定项置顶无法满足
- 为何不选：不采纳

### 固定项放独立数组，只持久化顺序
- 优点：与用户目录数据分离
- 缺点：渲染、拖拽、去重都要维护两套列表；顺序还要额外存一份
- 为何不选：不采纳：状态面更大，收益只有数据洁癖

### 只展示固定目录、不修改默认 gameDir
- 优点：不改变新装落点
- 缺点：默认 `.minecraft` 仍然指向 `$HOME`，issue 的「不知道在哪」没有真正解决
- 为何不选：不采纳

### 官方目录用前端 Tauri path API 计算
- 优点：不碰后端
- 缺点：`appDataDir` 在 Linux 是 XDG 目录、macOS 需要拼 `minecraft`（无点），跨平台规则分散
- 为何不选：不采纳：后端解析一次、所有客户端共用

## 影响

- `src-backend/qomicex-backend/src/settings.rs`（`official_game_dir()` / `default_game_dir()` + 单测，默认 `gameDir` 变更）
- `src-backend/qomicex-backend/src/models.rs`（`SystemInfoResponse.official_game_dir`）
- `src-backend/qomicex-backend/src/endpoints/system.rs`（响应字段）
- `src/types/index.ts`（`SystemInfo.officialGameDir`）
- `src/pages/Instances.tsx`（`ManagedDir.fixed`、合并固定项、禁用删除/改名、下拉与弹窗统一渲染）
- `qomicex-tauri-i18n/src/{zh-CN,zh-TW,zh-HK,en-US,en-GB,ja-JP,ru-RU}/instances.ts`（`officialDir`，子模块单独提交）
- `docs/junsi-dev-docs/3-API规范/API列表.md`（`/system/info` 新字段）

## 风险

- 新装默认游戏目录从 `$HOME/.minecraft` 变为官方启动器目录；老用户已保存的 `gameDir` 与实例路径不变。回滚只需还原默认值，不涉及数据迁移。
- 官方目录首次可能不存在：扫描为空，打开时才由后端 `create_dir_all` 创建。
- 与官方启动器共用目录时，两边对 `versions/`、`mods/` 的改动会互相可见（这是「共用一份游戏文件」的预期行为）。
- 用户清空 localStorage 后，固定项会重新插入到列表最前，自定义顺序丢失（与现有目录列表同样的语义）。
