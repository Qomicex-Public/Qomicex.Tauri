# ADR-053：插件错误遥测上报 + 灰度自动暂停

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-26 |
| 决策者 | AI Agent |

## 背景

PHASE1→1.5 任务②：启动器插件更新走灰度（rolloutPercent 预留），需补 opt-in 崩溃/错误遥测上报 → 商店端按异常率自动暂停灰度。上游两仓库均未实现（git fetch 确认）。

## 决策

①遥测 opt-in 默认关（telemetryEnabled=false），字段白名单：pluginId+version+errorType(launch_crash/plugin_load_failed/plugin_runtime_error)+launcherVersion（后端注入），禁路径/堆栈/隐私。②上报链路：前端捕获（plugin-loader activate 失败→plugin_load_failed；sandbox iframe/inline 运行时错误→plugin_runtime_error，60s 内存 Map 去重）→ launcher POST /api/telemetry/plugin-error（endpoints/telemetry.rs 校验白名单+注入 launcherVersion）→ 转发 store /api/v1/telemetry/plugin-error → D1 plugin_error_reports（migration 0008）。③store check-updates 对每条候选版本做 24h COUNT，超 PLUGIN_ERROR_PAUSE_THRESHOLD（env 默认 10）则不返回该版本（自动暂停灰度），rolloutPercent 逻辑保留。④plugin_id 匹配 `plugin_id IN (p.id, p.slug) OR LIKE '%.slug'` 覆盖 manifest.id 反向域名形态。舍弃：按下载数算异常率（下载数据不可得）、后端去重（前端即可）。

## 备选方案

### 方案 按错误数/下载数比率暂停
- 优点：更准确反映异常率
- 缺点：download_stats_daily 只有日期+plugin 级聚合，无版本级下载数，数据不可得
- 为何不选：弃用，简化为绝对错误数阈值

### 方案 后端去重上报
- 优点：多客户端聚合去重
- 缺点：增加后端状态复杂度，任务要求前端内存 Map 即可
- 为何不选：弃用，前端 60s 去重已满足

## 影响
- launcher: settings.rs/settings.ts/Settings.tsx 新增 telemetryEnabled；新增 endpoints/telemetry.rs + services/plugin_store.rs::report_plugin_error；plugin-loader.tsx/sandbox.ts 捕获点；i18n submodule 7 locale 新增 telemetry 文案
