# ADR-021：整合包本地导入（zip/mrpack）与实例导出（CF zip / MR mrpack）

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-16 |
| 决策者 | AI Agent + 用户 |

## 背景

用户要求为 Qomicex Launcher 添加整合包导入/导出：
1. **导入**：安装本地已下载的 `.zip`（CurseForge）/`.mrpack`（Modrinth）整合包文件。
2. **导出**：把已安装实例导出为 `zip(cf)` / `mrpack(mr)` 整合包。

调研结论（Gate 0）：`origin/main` 未实现——`/modpack/parse` 与 `install-direct` 的 `path` 分支为 stub，导出完全不存在；`qomicex-core-rust` 安装器仅做 override 解压，无导出能力。需求为本项目私有，自研。

现有基础：导入 UI（`ImportDialog`）已存在，调用 `POST /modpack/parse`（stub）→ `POST /modpack/install`（真实管道已通）；后端已具备 `zip` crate、axum `multipart`、manifest 解析函数与完整安装管道（下载包体→解析→装 MC+加载器→下载 mods→解 overrides）。

需求澄清结果：
- **导入行为**：mrpack 与 CF zip 都走完整管线——mods 逐文件走源 API 下载（mr：index 内 URL；cf：manifest `projectID:fileID` → CF API），**再**释放 overrides（overrides 承载 API 找不到的文件，如配置）。
- **导出策略**：mrpack 与 CF zip 都做**哈希反查**填充 `files[]`；查不到的 mods 进 `overrides`。
- **导出入口**：实例详情页「概况」快捷操作区按钮 + 导出弹窗（格式单选、勾选存档/截图）。
- **导出范围**：默认游戏内容（mods/config/scripts/resourcepacks/shaderpacks/datapacks/servers.dat），存档/截图可选勾选。

## 决策

### 1. 导入：parse 上传 + 管道本地分支

- `POST /modpack/parse`（multipart `file`，上限 4 GiB）：流式落盘到 `{BaseDir}/temp/modpack-uploads/{uuid}`（1 天自动清理），探测格式（`modrinth.index.json` → mr；`manifest.json` 且 `manifestType=minecraftModpack` → cf），复用现有解析函数返回 `ModpackParseResult` + 新增 `fileId` 句柄。
- `POST /modpack/install` 新增可选 `fileId`：`install()` 解析为临时文件路径，管道 `run_modpack_pipeline` 新增 `local_pack_path` 参数——跳过包体下载，用本地文件解析 manifest 并释放 overrides；mods 仍按源下载（mr：URL；cf：`projectID:fileID` 查 CF API），与用户「先下 mods 再放 overrides」的要求一致。安装结束（成败皆然）删除临时文件。
- `install-direct` 的 `path` 分支：同步解析本地文件（同格式探测）→ 后台管道（绝对路径直传，`local_path` 内部字段，不走 HTTP、不清理）。
- `ModpackInstallRequest` 新增 `local_path: Option<String>`（`#[serde(skip)]`，仅 install-direct 内部使用）。

### 2. 导出：`POST /modpack/export/{instanceId}`

同步生成 zip，`Content-Disposition: attachment` 返回字节（前端 300s 长超时 fetch blob 下载）。

- 源目录 = `{gameDir}/versions/{inst.name}`（版本隔离）或 `{gameDir}`；排除版本 json/jar、`libraries|versions|assets|logs|temp|crash-reports`、账户缓存（`usercache.json` 等）与未勾选的 `saves`/`screenshots`。
- **CF zip**：`manifest.json`（`minecraft.version` + `modLoaders[{id: "{loader}-{loaderVersion}"}]`、name/version/author、`files[]`、overrides） + `overrides/**`；mods 用 **CF fingerprint（32 位 MurmurHash2，SEED=1、MULT=1540483477、忽略空白字节 9/10/13/32）** 反查 `POST /v1/fingerprints` 得 `projectID/fileID`；mods 同时留在 `overrides/mods`（CF 惯例双份，files[] 供导入器下载、overrides 兜底）。
- **mrpack**：`modrinth.index.json`（formatVersion 1、dependencies{minecraft, loader}、`files[]` 含 path/hashes.sha1/env/downloads/fileSize、overrides） + `overrides/**`；mods 用 SHA1 反查 `POST v2/version_files`；**已解析 mods 不进 overrides**（避免重复）。
- **反查 best-effort**：失败（离线/无 key/限流）只影响 `files[]`，mods 回落 `overrides/mods`，导出不中断。

### 3. UI

- `src/components/ExportModpackDialog.tsx`（新）：格式单选（CF zip / MR mrpack）、勾选存档/截图、文件名预览、导出中/成功/失败状态。
- `src/pages/InstanceDetail.tsx`：概况快捷操作新增「导出整合包」按钮（faFileExport）并挂载弹窗。
- `src/components/ImportDialog.tsx`：`startModpackInstall` 透传 `source` + `fileId`（此前缺 source 会导致管道跳过 overrides 释放）。
- `src/api/instance.ts`：`exportModpack(instanceId, {format, includeSaves, includeScreenshots})`（300s 长超时）+ `ModpackExportResult{blob, filename}`。

### 4. core 库修正（哈希反查保留 files）

`qomicex-core-rust` `to_project_version_info_from_hash` 此前沿 C# 源显式 `Files=null`，导致 `get_project_versions_from_hashes_dict` 调用方拿不到文件下载 URL/大小/哈希。修正：
- `ModrinthFile` 模型补 `size`/`primary`（API 恒返回；C# 源模型有损缺失）。
- `to_project_version_info_from_hash` 映射 `files`（复用 `modrinth_file_to_version_file_info`）。
- 消费者 `services/local/mods.rs` 只取 `project_id`/`id`，不受影响。

### 5. i18n

`qomicex-tauri-i18n` submodule 新增 `dialogs.modpackExport.*`（zh-CN + en）与 `instanceDetail.overview.exportModpack`。

## 舍弃方案

- **CF 导入直接从 overrides 解出 mods（跳过 API 下载）**：用户明确否决——overrides 是 API 找不到的文件，mods 应逐文件走源下载（与 mr 一致），且 CF zip 部分 mods 可能在 overrides 之外。
- **mrpack 导出简化（mods 直接打 overrides、files[] 留空）**：用户选择完整方案（sha1 反查），代价是依赖网络与限流；已用 best-effort 兜底（反查失败自动回落简化行为）。
- **导出异步后台任务 + 进度**：同步生成对常规包体（几十 MB～1 GB）足够，前端 300s 超时兜底；异步会引入额外任务状态管理，收益低。

## 影响

- `src-backend/qomicex-backend/src/endpoints/modpack.rs`：parse/install/install-direct 本地分支 + export 端点 + DTO（`fileId`/`local_path`）。
- `src-backend/qomicex-backend/src/services/modpack_export.rs`（新）：内容收集、CF/MR 反查、zip 生成。
- `src-backend/qomicex-backend/Cargo.toml`：+`sha1`（crc32fast 曾引入、算法修正后移除）。
- `qomicex-core-rust`：ModrinthFile 模型 + 哈希反查 files 映射。
- 前端：`ExportModpackDialog.tsx`（新）、`InstanceDetail.tsx`、`ImportDialog.tsx`、`api/instance.ts`、`types/index.ts`。
- `qomicex-tauri-i18n`：zh-CN + en 文案。

## 验证

- `cargo test` 23/23（含 2 个 CF fingerprint 向量单测，向量用真实 CF API 交叉验证：`recipegraph-1.0.0.jar` → fingerprint 2715177757 → 精确命中 modId=1578679/fileId=8266592）。
- E2E（真实 API）：mrpack/CF zip 解析 ✓；CF 导出 files[] 命中真实 mod ✓；MR 导出 files[] 含 sha1/URL/size 且已解析 mods 不进 overrides ✓；排除规则 ✓；无 key 时 best-effort 降级 ✓。
- `pnpm run build`（tsc + vite）通过。


### 2026-08-16 更新

## 变更（2026-08-16）：导出升级为 HMCL 风格文件勾选

新增能力：导出前可查看完整文件树并逐个勾选要包含的文件。

- **新端点** `GET /modpack/export/files/{instanceId}`：返回完整递归文件树（`ExportTreeNode[]`：dir/file、`size` 子树累计、`fileCount`、children），与导出共用同一排除规则（版本 json/jar、`libraries|versions|assets|logs|temp|crash-reports`、账户缓存）；**saves/screenshots 不再排除**（是否包含交由前端勾选）。
- **导出请求体扩展**：`ModpackExportRequest` 新增可选 `includeFiles: string[]`（相对路径白名单）。语义：不传 = 全量（旧行为完全兼容，saves/screenshots 仍由 `includeSaves`/`includeScreenshots` 开关控制）；传入 = 由白名单唯一决定包含内容（覆盖 saves/screenshots 开关）。过滤规则：文件必须命中白名单；目录仅当其子树存在命中文件时保留（保证 zip 路径完整）。
- **导出实现重构**：`modpack_export.rs` 改为「先建树（`collect_export_tree`，含累计 size/file_count）→ 展平（`flatten_tree`）→ 过滤（`filter_by_include` 或旧开关）→ 打包」；mods 反查只针对过滤后保留的 mods。
- **UI**：`ExportModpackDialog` 重写为文件树勾选——目录默认折叠、逐文件 checkbox（目录支持全选/半选 indeterminate、点击递归全选/取消）、顶部全选/全不选 + 已选统计（N 项 · 大小）、加载/失败重试/空态；旧「包含存档/截图」开关并入树（saves/screenshots 默认不勾）。导出时全选走旧语义（`includeSaves=true`+`includeScreenshots=true`）避免巨型白名单，部分选择传 `includeFiles`。
- **i18n**：`dialogs.modpackExport.*` 新增 selectAll/deselectAll/selectedSummary/loading/loadFailed/retry/empty/fileCount/expand/collapse/cat*（zh-CN/en-US/en-GB）。

### 2026-08-16 更新 2

## 变更（2026-08-16）：导出可自定义包名/版本/作者

导出对话框新增「包信息」区块（名称/版本/作者输入框），支持导出时覆盖包元数据：

- **请求体扩展**：`ModpackExportRequest` 新增可选 `name`/`version`/`author`（trim 非空时生效，覆盖实例 `modpackName`/`modpackVersion`/`modpackAuthor`；不传完全向后兼容）。
- **写入位置**：CF `manifest.json` 的 `name`/`version`/`author`；MR `modrinth.index.json` 的 `name`/`versionId`（**mrpack 标准格式无 author 字段，不写入**）。
- **下载文件名**：优先请求 `name`（trim 非空），其次实例 `modpackName`，最后实例名。
- **UI**：对话框格式选择下方插入包信息区块，默认值带出实例元数据（名称=modpackName||实例名、版本=modpackVersion||1.0.0、作者=modpackAuthor）；**切到 Modrinth 格式时隐藏作者输入框**（避免误导）；仅本次导出生效，不写回实例。
- **后端**：`meta_override(value, fallback)` 纯函数统一覆盖解析（trim 非空优先），新增单测覆盖。
- **i18n**：`dialogs.modpackExport.*` 新增 packInfo/packName/packVersion/packAuthor（zh-CN/en-US/en-GB）。

### 2026-08-16 更新 3

## 变更（2026-08-16）：导出升级为「选路径 + 异步进度 + 可取消」

- **异步任务化**：`POST /modpack/export/{instanceId}` 从同步返回 zip 改为**创建导出任务**（返回 `202 { taskId }`）。新端点：`GET /modpack/export/task/{taskId}`（轮询 status/stage/percent/currentFile）、`POST /modpack/export/task/{taskId}/cancel`（取消）、`GET /modpack/export/task/{taskId}/download`（未传 targetPath 时取 zip 字节）。
- **进度与取消**：`build_export_zip` 增加进度回调（阶段 `lookup` 识别文件指纹 0-30% → `manifest` 生成配置文件 30-35% → `packing` 打包游戏文件 35-100% 逐文件 currentFile）与 `AtomicBool` 取消标志（反查批次间/逐文件前检查，置位尽快中断）。
- **保存路径**：请求体新增可选 `targetPath`。传了由后端任务完成后 `fs::copy` 到目标（复制成功即删临时文件）；不传则产物保留 `{BaseDir}/temp/export-{taskId}.zip` 供 download 端点读取（浏览器 dev fallback）。
- **任务管理**：新 `services/export_tracker.rs` `ExportTaskManager`（挂 AppState），终态任务保留最近 20 个、超限淘汰最老并清理临时文件。
- **UI**：点「开始导出」先弹系统保存对话框（Tauri `plugin-dialog save()`，默认 包名.zip/mrpack）选路径 → 起任务 → 进度 Dialog（标题「正在导出...」+ 自绘进度条 + 当前操作文案 + 取消按钮）；**导出中 `closeOnBackdrop=false` + `closeOnEsc=false` 且隐藏标题栏关闭钮（点空白/ESC 不关，防误触）**；点取消先 `msgConfirm` 确认；完成停留显示「✓ 导出完成（已保存到: 路径）」（此时可点空白关闭）、取消/失败显示对应状态。
- **i18n**：`dialogs.modpackExport.*` 新增 exportingTitle/stageLookup/stageManifest/stagePacking/cancelExport/cancelConfirm/exportCancelled/exportSaved/exportSavedTo（zh-CN/en-US/en-GB）。
