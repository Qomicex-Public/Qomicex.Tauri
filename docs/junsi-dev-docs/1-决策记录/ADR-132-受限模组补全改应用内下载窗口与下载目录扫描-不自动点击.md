# ADR-132：受限模组补全改应用内下载窗口与下载目录扫描，不自动点击

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-18 |
| 决策者 | AI Agent |
| 关联 | ADR-118（分发受限文件阻塞清单）、ADR-123（精确版本文件页） |

## 背景

ADR-118 / ADR-123 落地后，分发受限文件要走「打开精确文件页 → 用户在浏览器里下载 → 回启动器选择/拖入文件」。实际使用中仍然是整条链路上最麻烦的一段：浏览器下载完后要自己找文件、逐条对应，整合包有十几个受限文件时尤其明显。

用户提出的方向是「隐藏 webview 打开链接自动点下载，再交给启动器下载器」。这个方向需要拆开看：

- **隐藏窗口自动点击不可行。** 受限状态是作者在项目设置层关闭第三方分发的明确意愿，页面自动化点击属于绕过该开关，同时隐藏窗口不产生广告曝光，作者与平台的收益都拿不到，与「作者既有收益」的目标相反。CF 页面还有 Cloudflare 与登录态，自动化会随页面改版随时失效。
- **接管用户自己的点击可行且合规。** 用户在文件页上点 Download 是 CF 期望的流程，广告照常展示；启动器只需接住这次下载，省掉「下载完再回来选文件」。

Tauri 2.11.3 / wry 0.55.1 已提供 `WebviewWindowBuilder::on_download`，三平台均有实现（Windows WebView2 `add_DownloadStarting`，macOS WKWebView download delegate，Linux WebKitGTK download-started），`DownloadEvent::Requested { destination }` 可改落点，返回 `false` 可取消，`Finished { path, success }` 给出落盘路径。

## 决策

1. 新增 Tauri 命令 `open_blocked_download_window(instanceId, files, title)`，用独立小窗（label `cf-download`）加载**精确文件页**；`files` 每项为 `{fileId, fileName, url}`，单个文件也传单元素数组。每个 url 必须是 https 的 `curseforge.com` / `www.curseforge.com` 且路径含 `/files/`：这个窗口的结果会被当成可信输入自动补全，放开到任意站点等于给任意网页一个往实例里塞文件的入口。另提供 `close_blocked_download_window`，对话框关闭时一并关闭窗口并作废队列。
   - 命令**必须声明为 `async fn`**：`#[tauri::command]` 的同步命令在 IPC 回调线程（Windows 上即 UI 线程）上直接执行，`WebviewWindowBuilder::build()` 会阻塞等待 WebView2 控制器的异步创建回调，而该回调又需要同一个消息循环 → 窗口白屏、关不掉、启动器假死。async 命令被宏切到 tokio 线程执行，建窗只投递消息。
2. 小窗是**标签队列**：`open_blocked_download_window(instanceId, files, title)` 接收整批文件，一次只加载当前标签的页面（N 个 CF 页面同时渲染会吃掉几百 MB 内存）。顶部工具栏（刷新 / 浏览器打开 / 一键下载 / 标签列表 / 完成计数）由 `on_page_load(Finished)` + 延时兜底的 `eval` 注入固定定位 DOM（外部站点的加载事件不保证按时到达）。
   - 按钮动作通过 `window.open('https://qomicex-cfdl.invalid/...')` 产生新窗口请求，由 `on_new_window` 拦截执行并拒绝新窗口；**不能用 `location.href`**：取消导航会先销毁当前文档，留下空白文档，接着又被下一次 eval 撞上，形成黑屏循环（实测触发）。
   - 外部页面仍然没有 IPC 权限；工具栏脚本异常/自动点按找不到按钮时经同一伪地址上报（`err/`、`auto/missing`），每个文档只报一次。
3. `on_download` 收到 `Requested` 时**取消** WebView2 的下载（返回 `false`），把当前标签移出队列并向主窗口 `emit_to("main", "blocked-download-requested", {instanceId, fileId, url})`；队列还有标签就导航到下一个，没有就关窗。
   - 原因：CF 下载确认页倒计时结束后用 `mode:"cors", credentials:"omit"` 的 fetch 取 CDN 文件再交给浏览器；在 WebView2 里这条链路只触发 `Requested`，既不落盘也不回调 `Finished`，表现为窗口一直挂着、没有任何反应。
   - 工具栏「快速下载」：用户显式开启后，在**精确文件页**（路径含 `/files/`）自动点击**该 fileId** 的下载入口（选择器带 `/download/{fileId}`，避免命中「下载 CurseForge 客户端」等同名按钮），倒计时页（`/download/`）不重复点；按钮找不到或脚本异常时立即关闭自动模式并写 `[cf-download]` 日志。非 `*.forgecdn.net` 的下载事件一律取消且不消耗标签页。全程只在可见窗口、用户手动开启、逐页串行执行，页面与倒计时照常展示，不隐藏窗口、不拼下载地址。
3. 新增 `POST /modpack/blocked/{instanceId}/fetch`（body `{fileId, url}`）：只接受 `https://*.forgecdn.net` 地址（地址来自页面，不校验等于开放任意 URL 下载面），流式下载到 `{gameDir}/temp`，复用 `accept_blocked_file` 做 SHA-1 校验与落盘，临时文件随后删除。
4. 进度：进程内 `HashMap<"instanceId:fileId", {downloaded,total,done,error}>`，`GET /modpack/blocked/{instanceId}/fetch/{fileId}/progress` 供对话框每 400ms 轮询，对应行显示百分比；下载完成后前端用返回的剩余清单收尾。
5. 文件页上的 Download 若是 `target=_blank`，WebView2 会把它交给系统浏览器，事件不经过本窗口。`on_new_window` 返回 `Deny`，仅当目标是 CurseForge 主域**或 `*.forgecdn.net` 下载域**时在同窗 `navigate`；站外弹窗（广告）直接拒绝。窗口内保留 `[cf-download]` 日志（弹出地址/放行结果/下载请求），便于定位页面改版后的断点。
6. 小窗 label 不写进 `capabilities/default.json`：外部页面没有 IPC 权限，无法调用任何命令。
7. 新增 `POST /modpack/blocked/{instanceId}/scan-downloads`：扫描 `dirs::download_dir()` 下的 `.jar` / `.litemod`，按 `sha1` 匹配清单，无哈希的旧条目退回文件名匹配；命中的复制进 `mods/` 并移出清单，源文件不删不移。候选上限 200 个、单文件上限 512 MiB、按修改时间倒序，避免下载目录较大时把按钮卡住。
8. 前端每行按钮改为「应用内下载」（仅 `filePageUrl` 存在且运行在 Tauri 时），页脚新增「全部打开」（整批标签）与「从下载文件夹补全」；命令不可用则退回系统浏览器。多个文件可并行下载，对话框按 `fileId` 分别显示百分比。

## 备选方案

### 方案 隐藏 webview 自动点击下载
- 优点：用户零操作
- 缺点：绕过作者开关与第三方分发条款；隐藏页面无广告曝光，作者无收益；Cloudflare / 页面改版会让自动化随时失效
- 为何不选：明确不采纳：合规红线未变（ADR-118）

### 方案 在页面里注入脚本读取 CDN 链接，再交给后端下载
- 优点：能做进度条、断点续传
- 缺点：性质与自动点击相同；CDN 链接短期签名且可能绑 cookie，稳定性差
- 为何不选：明确不采纳：同上

### 方案 只做下载目录扫描（B）
- 优点：改动最小，不新增窗口
- 缺点：用户仍要回启动器点一次；文件名被浏览器改写时容易漏匹配
- 为何不选：不采纳为唯一方案，但作为兜底保留（页脚入口）

### 方案 监控下载目录、自动导入新文件
- 优点：完全自动
- 缺点：需要常驻文件监听，会读用户所有下载；误判风险与隐私成本都高
- 为何不选：不采纳：改为用户显式点击的一次性扫描

## 风险

- CurseForge 的 Download 按钮行为（直接触发下载 / 新窗口 / 二次确认）未在真实页面验证过（本机请求页面返回 403）。上线前必须实测：若按钮走新窗口，`on_new_window` 的同窗导航已覆盖；若走二次确认页，用户多点一次即可。
- Cloudflare 可能对内嵌 WebView2 发起挑战；页面内可完成验证，不影响合规流程。
- 事件按 `fileId` 回填，用户在窗口里下载了另一个版本时会得到校验失败提示，文件不会进 `mods/`。
