# ADR-099：修复 #116：存档卡片选中态丢失基础内边距导致内容上浮

## 背景

Issue #116「实例详情地图列表错误」报告：实例详情「存档」tab 中选中一个存档后内容会上浮。原报告仅一句现象 + 截图，无复现步骤与日志，需要先确定触发条件是「切换 tab」还是「点选卡片」。

用 Playwright 注入 Tauri mock + 独立后端（真实 /instance/{id}/files/saves/metadata）在 1280×884 实测四个状态（未选中 / 悬停 / 选中 / 取消选中），排除法结论：
- 「切换 tab 导致上浮」不成立——contentCol / tabContent / section 的 top 在 概况 与 存档 两种 tab 下均为 140px，无位移。
- 「点选卡片导致上浮」成立，且量化精确：

| 状态 | CardContent padding (上/右/下/左) | 卡片高 | 内容距卡顶 |
|---|---|---|---|
| 未选中 | 16 / 16 / 16 / 16 | 82px | 17px |
| 悬停 | 16 / 16 / 16 / 40 | 82px | 17px |
| 选中 | **0** / 24 / 24 / 40 | **74px** | **1px** |
| 取消选中 | **0** / 24 / 24 / 40 | **74px** | **1px** |

即选中后内容上跳 16px、卡片矮 8px，与「内容会上浮」完全吻合（注意取消选中后仍保持塌陷，直到 hover 才恢复）。

## 决策

根因：src/components/SaveCard.tsx 的 CardContent 把基础内边距 p-4 写进了条件表达式的 else 分支——

    selectMode || selected ? 'pl-10' : 'p-4 group-hover:pl-10 focus-within:pl-10'

选中态只传 pl-10，p-4 整体失效，只剩 plugin-ui CardContent 组件默认的 `p-6 pt-0`，于是 padding-top 变 0（右侧/下侧反而从 16 变 24，因为默认 p-6 生效）。

修复：把 p-4 移到条件外，与同为列表卡片的 ModCard / ResourcePackCard / ShaderCard / DataPackCard 采用完全一致的既有范式：

    cn('relative flex items-center gap-4 p-4 transition-[padding] duration-200',
       selectMode || selected ? 'pl-10' : 'group-hover:pl-10 focus-within:pl-10')

选中的语义只应改变左内边距（给复选框让位），基础内边距必须恒在。

归因：git blame 显示该行由 445b70b「资源包/光影包/数据包等页签与 Mod 列表行为对齐」引入——该提交给 SaveCard 补 selectMode/复选框时，把 p-4 误放进了 else 分支，而其余四个卡片都写对了，属单点偏离。<br>
范围界定：该反模式全仓库仅此一处（grep `selectMode \|\| selected ? '(pl|p)-…' : '` 只命中 SaveCard）。

验证（双向）：
1. 负对照——临时抽掉修复重跑探针，复现 padding-top=0px / 卡片高 74 / 内容距卡顶 1px，证明该测量确实能捕获此缺陷（不会「两边都过」）。
2. 还原修复后四状态全部稳定在 16px / 82px / 17px。
3. 质量门禁：tsc --noEmit 退出码 0（与洁净基线一致）；eslint 该文件 0 问题；prettier 告警经比对为存量（未改动的原文件同样不符，全仓库 501 个文件不符），未引入新债。

## 备选方案

### 方案 在 SaveCard 里为选中态显式补回上下内边距（如 'pt-4 pb-4 pl-10'）
- 优点：改动局限在选中分支，字面直观
- 缺点：与其余 4 个卡片的范式仍不一致，未来对齐时容易再次被改坏；把「基础内边距」与「选中增量」两个概念混在一个分支里，正是本次缺陷的成因
- 为何不选：不采纳：治标。范式统一才是根治，且 p-4 恒在条件外后条件分支只表达「左侧让位」这一个语义。

### 方案 改 plugin-ui 的 CardContent 默认内边距（去掉 pt-0）
- 优点：一处改动影响所有卡片
- 缺点：CardContent 的 p-6 pt-0 是 shadcn 继承来的通用默认值，被 Dialog、账户卡等多处依赖；改它属于跨组件行为变更，会波及大量非相关界面
- 为何不选：不采纳：影响面远超本 issue 范围，且并非所有调用方都传 p-4 覆盖。

### 方案 让选中态只切换 checkbox 可见性、完全不改内边距
- 优点：零位移
- 缺点：复选框会与 48px 图标重叠（该 padding 正是为让位而存在），属于既有设计约束
- 为何不选：不采纳：会破坏既有的复选框避让设计。

## 影响
- src/components/SaveCard.tsx（1 行功能改动 + 3 行注释）
- 实例详情「存档」tab：单选 / 多选模式 / Ctrl+点击 / 拖拽框选下的卡片行高与内容对齐
- 无 API、后端、i18n、数据契约变更
