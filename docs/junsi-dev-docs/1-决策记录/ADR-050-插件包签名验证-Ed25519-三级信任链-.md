# ADR-050：插件包签名验证（Ed25519 三级信任链）

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-25 |
| 决策者 | AI Agent |

## 背景

当前 .qplugin 上传无签名，社区上传即触发供应链投毒风险。需建立商店根钥签发开发者公钥 → 开发者密钥签每个 release 的三级信任链，包内 signature.json，启动器安装/更新时验签。

## 决策

Ed25519 三级信任链：①商店根钥（CF Worker secret PLUGIN_ROOT_PRIVATE_KEY 持有私钥，launcher 内置根公钥常量）签发开发者公钥证书 signature.cert.json；②开发者密钥对 release 包体签 signature.json；③包内嵌 signature.json + signature.cert.json，launcher 完全离线自洽验签（upload 强制、store-install 有签名则验无签名放行老版本、install_from_dir dev 路径豁免）。signedHash = SHA-256(规范化 manifest+按 path 排序的文件清单)。规范化 JSON = 递归排序键 + 无空白，两端（Web Crypto / ed25519-dalek）实现一致保证可复现哈希。兼容策略：新上传必须有签名，老版本不强制重签。

## 备选方案

### 方案 launcher 安装时向商店 API 拉取开发者公钥
- 优点：包体小，公钥集中管理
- 缺点：upload 路径必须联网，离线装不了；store-install 依赖 store 可用性
- 为何不选：选包内嵌证书，离线自洽

### 方案 upload 与 store-install 都强制签名
- 优点：策略严格
- 缺点：商店老版本无法安装，违背不强制重签的降级策略
- 为何不选：store-install 有签名则验、无签名放行

## 影响
- store: migrations/0007 + developer_keys 表、POST /api/v1/developer/keys、上传版本验签
- launcher: services/plugin_signature.rs 新模块、ed25519-dalek 提为硬依赖、install_from_package 加 require_signature、新错误码 PLUGIN_SIGNATURE_*
- keygen 脚本 scripts/plugin-keygen.mjs
- CLI 任务⑤ 依赖本 ADR 的签名格式
