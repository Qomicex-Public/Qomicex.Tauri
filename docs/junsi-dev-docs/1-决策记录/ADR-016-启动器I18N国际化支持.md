# ADR-016：启动器 I18N 国际化支持（轻量自研 + 全量迁移 + 错误码前端映射）

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-15 |
| 决策者 | AI Agent |

## 背景

用户要求为启动器添加 I18N 支持。现状：`AppSettings.language` 字段与设置页「外观」Tab 的「界面语言」下拉框早已存在（zh-CN/en 选项），但**从未实际生效**（只保存值，UI 不切换）；前端约 1000+ 处硬编码中文 UI 文案（跨 12 页面 + 50 组件，全项目含注释/数据字典约 1828 处中文字符）；后端 22 个 endpoint 返回中文错误 message（前端 `ApiError.displayMessage` 直显）。无任何 i18n 库。

需求确认：轻量自研方案 + 全量迁移所有前端文案 + 后端错误消息一并处理。

## 决策

### 1. 基础设施：轻量自研（零新依赖）

- `src/i18n/`：`I18nProvider`（React Context）+ `useI18n()` hook（返回 `{ lang, t, setLanguage }`）+ 按模块拆分的 zh-CN/en TS 资源文件。
- 类型安全：`TranslationSchema = DeepStringify<typeof zhCN>`（叶子值放宽为 string，仅校验 key 结构）；`en/index.ts` 用 `satisfies TranslationSchema` 编译期强制 zh/en key 结构一致；`t()` 的 key 参数类型为 `DeepKeys<TranslationSchema>`（递归模板字面量类型），key 拼错编译期报错。
- 插值：`t('key', { param })` 替换翻译值中的 `{param}` 占位符。
- 语言持久化：`localStorage('qomicex-language')` 即时生效；`I18nProvider` 订阅 `onSettingsChange`（后端 `put /settings` 广播）双向同步 `settings.language`，多窗口/重启后一致。
- 挂载：`I18nProvider` 包在 `App.tsx` 最外层（`RunningProvider`/`MessageBoxProvider` 之外），全局可用。
- 语言切换：设置页下拉 `onChange` 同时 `update('language', v)`（持久化到后端）+ `setLanguage(v)`（即时切换，无刷新）。

### 2. 迁移策略：按模块分批，全量覆盖

- 翻译模块命名空间 = 页面/功能域：`common`（通用按钮/提示）、`layout`（外壳）、`settings`、`dashboard`、`instances`、`instanceDetail`、`downloads`、`accounts`、`accountDetail`、`resource`、`resourceDetail`、`connect`、`running`（启动流程）、`plugins`、`dialogs`（通用弹窗/卡片）、`tools`（工具箱/调试/日志/闪屏）。
- 每个模块 zh/en 文件独立 → 各批 subagent 并行迁移无文件冲突（互不读写同一文件）。
- 已迁移：外壳（Sidebar/Layout）、启动流程（RunningContext）、设置页 category 导航 + 外观核心项（批 0）。
- 迁移规则：只替换面向用户的 UI 字符串（含 aria-label/title/placeholder/确认框/toast/空态）；注释、数据字典、API 字段、URL、专有名词不迁移；插值模板字符串 `\`xxx ${v}\`` → `{placeholder}` + params。
- 组件内用 `tRef` 模式（`const tRef = useRef(t); tRef.current = t`）保持 `useCallback` 依赖稳定。

### 3. 后端错误消息：前端错误码映射（后端零改动）

- 后端错误响应已有稳定 `code` 字段（`ApiError` → `{ code, message, detail, ... }`）。
- `src/api/client.ts` 增加模块级翻译钩子 `setApiErrorTranslator(fn)`；`ApiError.displayMessage` getter 优先走翻译器，未命中回退后端 message（中文兜底）。
- `src/i18n/errors.ts` 维护 `CODE_TO_KEY` 映射（`NOT_FOUND`/`FORBIDDEN`/`BAD_REQUEST`/`INTERNAL_ERROR`/`UPSTREAM_ERROR`/`REQUEST_TIMEOUT`/`UNKNOWN_ERROR`/`LICENSE_*` 系列/`TOKEN_EXPIRED`/`MC_API_ERROR`/`FS_AUTHORIZATION_REQUIRED`/`PLUGIN_MISSING_DEPENDENCY`），`I18nProvider` 语言变化时刷新注入。
- 理由：后端 22 个端点逐个做 Accept-Language 多语言改动面巨大且易漏；错误码已稳定存在，前端统一映射一处生效，成本低、覆盖全；未映射 code 仍有中文兜底。

## 备选方案

### 方案 react-i18next（i18next + react-i18next）
- 优点：社区标准、功能全（复数/插值/懒加载）、生态成熟
- 缺点：新增运行时依赖与包体积；对本地桌面应用（无 SSR）收益有限；迁移所有组件 API 与自研方案工作量相当
- 为何不选：用户明确选择轻量自研；项目风格倾向零依赖轻量实现

### 方案 后端 Accept-Language 多语言
- 优点：后端返回原生语言消息
- 缺点：22 个 endpoint 全部改造、消息集中管理困难、遗漏风险高
- 为何不选：错误码已稳定，前端映射成本低且覆盖全

### 方案 只搭框架不迁移
- 优点：改动最小
- 缺点：切换语言无可见效果，无法验证"支持"
- 为何不选：用户要求全量迁移

## 影响

- 新增 `src/i18n/`（Provider、types、errors 映射、16 个 zh/en 翻译模块）
- `src/api/client.ts`：`setApiErrorTranslator` 钩子 + `displayMessage` 优先翻译
- `src/App.tsx`：挂载 `I18nProvider`
- 全部 12 页面 + 50 组件：分批 `t()` 迁移
- 设置页语言下拉：联动即时生效
- 无构建命令/依赖变更（零新依赖）

## v1.1 修订：语言集扩展为 7 语言 BCP 47 全码（2026-08-16）

- **语言集**：`zh-CN` / `zh-TW`（台湾繁体）/ `zh-HK`（香港繁体）/ `en-US` / `en-GB` / `ja-JP` / `ru-RU`，统一 BCP 47 全码（lang-region）。
- **资源位置变更**：全部语言资源迁入 submodule `qomicex-tauri-i18n/src/{lang}/`（18 个 TS 模块 + `game-settings-descriptions.json` 583 键/语言）；启动器 `src/i18n/` 仅保留 Provider/错误映射/类型 re-export。**编辑翻译必须改 submodule 内文件并在 i18n 仓库单独提交推送**。
- **zh-TW 升级**：由占位（re-export zh-CN）升级为真实台湾繁体翻译；新增 zh-HK（網絡/軟件/用戶/帳戶/上載/數據 等香港用词）、ja-JP、ru-RU 全量翻译（含游戏设置描述 JSON）。
- **结构保障**：每语言 `index.ts` 用 `satisfies TranslationSchema` 编译期强制与 zh-CN 键结构一致；`RESOURCES: Record<Lang, TranslationSchema>`。
- **启动器**：`src/i18n/lang.ts` `LANGS`/`SUPPORTED` 扩展 7 项；`detectSystemLang()` 增加 zh-hk→zh-HK、ja→ja-JP、ru→ru-RU 映射。
- **后端**：`options.rs` `include_str!` 扩展 3 份新语言 JSON（共 7 语言描述表，未覆盖语言回退 en-US）；`to_minecraft_lang` 增加 zh-HK→zh_tw、ja-JP→ja_jp、ru-RU→ru_ru（Minecraft 无 zh_hk 官方码，香港用户用繁体 zh_tw）。
- 验证：`tsc --noEmit` 0 错误；`cargo test services::options::tests` 5/5；四语言 JSON 键集与 zh-CN 完全一致（583 键）。
