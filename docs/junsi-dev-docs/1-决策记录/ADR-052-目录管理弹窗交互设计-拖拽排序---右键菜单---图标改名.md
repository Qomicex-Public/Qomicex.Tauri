# ADR-052：目录管理弹窗交互设计：拖拽排序 + 右键菜单 + 图标改名

| 属性 | 内容 |

| 日期 | 2026-08-26 |
| 决策者 | AI Agent |

## 背景

目录管理弹窗（src/pages/Instances.tsx 的 dirManager Dialog）在首轮重构后采用"行点击选中+绿色当前使用标签+铅笔图标激活改名"。用户随后要求增加排序能力。排序需支持用户自定义顺序并跨会话保持。

## 决策

排序采用 HTML5 原生拖拽（行左侧 6 点手柄 faGrip 触发，drop-to-end 区域可移至末尾），顺序即 managedDirs 数组顺序，saveDirs 写 localStorage 天然持久化；右键菜单复用 src/components/ContextMenu.tsx，四项操作：设为当前使用（当前项禁用）/重命名/打开目录/移除；名称编辑从始终可编辑 Input 改为文本 + 铅笔按钮激活（Enter/失焦提交，Esc 取消，空名不保存）；当前使用目录仍以绿色"✔ 当前使用"标签标识，不做固定置顶。

## 备选方案

### 方案 排序按钮（名称/路径升降序）
- 优点：实现简单，零依赖，无拖拽误触风险
- 缺点：不支持用户自定义顺序，需额外持久化排序状态
- 为何不选：用户明确选择拖拽

### 方案 引入 @dnd-kit/core 拖拽库
- 优点：触屏/动画体验更完善，live 重排更顺滑
- 缺点：新增依赖，行内已有 Input/按钮，过度设计
- 为何不选：桌面端 HTML5 DnD 已够用

### 方案 当前目录固定置顶
- 优点：当前目录一目了然
- 缺点：与绿色标签冗余，打乱用户自定义顺序
- 为何不选：用户选择保留绿色标签
