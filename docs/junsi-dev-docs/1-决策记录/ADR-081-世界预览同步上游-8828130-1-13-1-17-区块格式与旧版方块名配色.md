## 背景

上游 C:\Project\world-viewer 在 2026-09-16 19:52 提交 8828130（fix(world): 支持 1.13-1.17 区块格式与旧版方块名配色）。本项目世界预览移植于 b2c2c0e（同日 00:20），早于该提交，因此该缺口在本项目同样存在。

两处缺陷：
1. 1.13-1.17 的区块把 sections 放在 Level 下、Palette 与 BlockStates 作为两个平级标签，而解析器只认 1.18+ 的根级 block_states。结果 1.14.4/1.16.5 存档被解析成空 section，地图一片空白（实测渲染 0 像素）。
2. 1.13 扁平化重命名了大量方块但外观未变，而内置颜色表按现代名建键。1.0-1.12.2 存档拿旧名查表全部落空、退回兜底灰 #505050（实测 1.8.9 地表 68% 的列落灰），且 minecraft:grass 被 is_foliage 误判而乘绿呈暗绿。

本项目已在 ADR-080 中修复了上游 ChunkKey 不含维度的缺陷，上游本次提交未涉及该点，故无冲突。

## 决策

采用「适配新架构」方式同步，而非逐字翻译：

1. 路径改写 crate::* → super::*（目标模块嵌套在 services/world_view/ 下）。
2. 上游独立 tests/palette_packing.rs 与 tests/legacy_colors.rs 并入 services/world_view/ported_tests.rs 内的 mod。原因是本项目后端是 bin crate、无 lib target，integration tests 目录不可用。
3. testing.rs 追加导出 BlockStates/Section，让测试驱动真实生产类型而非副本。
4. 保留上游英文注释原文，与既有 world_view 模块风格一致。
5. 上游硬编码存档路径经本机实测存在（1.6.4/1.8.9 在 C:\Minecraft，1.14.4 在 C:\Minecraft，1.16.5 在 C:\.minecraft），原样保留。

核心实现：
- palette.rs：LEGACY_ALIASES（55 项旧名→现代名，覆盖整个 1.0-1.12.2 区间，不按版本枚举）+ legacy_alias()，在 vanilla_color() 查表前解析；补 56 项缺失颜色。
- region.rs：BlockStates 新增 spans 字段与 from_parts()，由 long 数组长度反推打包布局（无需读版本号）；palette_index 按 spans 分流连续/补齐两种取位；parse_sections 新增 legacy_block_states()，fast parser 新增 Palette/BlockStates 分支与 parse_legacy_palette()/parse_legacy_block_states()。

顺带修复：palette_index 在 bits==0 且 data.is_some() 时执行 64/0 panic（上游同样存在），现已提前返回 Some(0)。

未采纳项：无，上游本次提交功能与修复全部同步。端点契约不变。

## 备选方案

### 方案 逐字翻译（含测试单独建文件）
- 优点：与上游形态最接近，后续 diff 对照容易
- 缺点：本项目后端为 bin crate 无 lib target，tests/ 目录的 integration test 无法访问 crate 内部模块；强行建文件需额外改造 crate 结构
- 为何不选：不选：为形式一致而改造 crate 结构，收益低于成本

### 方案 不移植，仅升级到上游版本
- 优点：零维护成本
- 缺点：本项目已把领域层移植为后端服务形态，上游 world-viewer 的 lib.rs 强依赖 Tauri（AppState/URI scheme protocol），无法直接替换
- 为何不选：不选：架构不兼容，ADR-080 已论证过

### 方案 适配新架构（采纳）
- 优点：改动局部、可测试、与现有分层一致；测试驱动真实生产类型
- 缺点：领域层在主仓与上游各一份，后续上游演进仍需手工同步
- 为何不选：采纳：与本项目既有 world_view 模块风格一致，验证充分

## 修订记录

### 2026-09-16：处理 PR #96 审查意见（Sourcery）

Sourcery 报告：`piston_head`/`piston_extension` → `minecraft:piston`、`wooden_slab`/`double_wooden_slab` → `minecraft:oak_slab` 会返回灰色 unknown。

**核实结果（部分成立）**：

| 别名 | 审查断言 | 实测 | 结论 |
|---|---|---|---|
| `wooden_slab` / `double_wooden_slab` | 返回 unknown 灰 | `src=vanilla` `[125,125,125]` | **断言不成立**——被 `contains("slab")` 后缀规则兜住；但颜色是石灰色而非木色，**另有真问题** |
| `piston_head` / `piston_extension` | 返回 unknown 灰 | `src=unknown` `[80,80,80]` | **成立**——别名是空操作（目标名不在颜色表） |

**修复**：

- 颜色表补 `minecraft:piston` `[110,110,110]`、`minecraft:piston_head` `[110,110,110]`、`minecraft:sticky_piston` `[90,130,90]`（后两者是 1.12.2 id=29/34 的直接名称，同属灰名单）
- 颜色表补 `minecraft:oak_slab` `[156,127,78]`，让两个木板台阶别名落到木色而非通用规则的石灰色

**新增回归护栏**（防止同类问题复发）：

- `legacy_colors::alias_targets_all_resolve_to_colours`——扫描全部 55 项别名，断言每个目标名都能解析出非 unknown 颜色。负向验证：移除新增的两条颜色后精确复现审查报的两个别名。
- `legacy_colors::legacy_slab_aliases_are_wood_coloured`——断言木板台阶是木色 `[156,127,78]` 而非石灰色。
- `palette::legacy_aliases()` 访问器 + `testing::legacy_aliases()` 转发，让护栏扫描真实表而非副本。

**偏离上游**：`ported_tests.rs` 中 `minecraft:wooden_slab` 的期望值由上游的 `[125,125,125]` 改为 `[156,127,78]`（已加注释说明）。上游把石灰色兜底固化为期望值，属于把缺陷写进测试。

验证：`cargo test` 182/182 全绿；`cargo fmt --check` 通过。
