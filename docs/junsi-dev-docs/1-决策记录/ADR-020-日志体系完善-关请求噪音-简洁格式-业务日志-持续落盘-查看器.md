# ADR-020：日志体系完善（关请求噪音 + 简洁格式 + 业务日志 + 持续落盘 + 查看器）

| 属性 | 内容 |

| 日期 | 2026-08-15 |
| 决策者 | AI Agent |

## 背景

用户反馈：**日志系统提取不出有效信息，启动器出问题看日志什么都看不出来**。诊断现状：

1. **噪音淹没**：`TraceLayer::new_for_http()` + `EnvFilter("info,tower_http=debug")` 让 tower_http 在 DEBUG 级为**每个请求**打 `on_request`/`on_response` 两条日志（含 `request{method=... uri=...}` span），每几 ms 一条重复信息，占满 2000 条环形缓冲。
2. **格式冗长**：`2026-08-15T20:14:01.815190Z DEBUG request{...}: tower_http::trace::on_request: started processing request`——带 span 上下文 + 长 target，无 `[时间] [模块]` 简洁结构。
3. **业务日志缺失**：启动（launch）、安装（install）失败路径**完全不进日志**（只写前端 ApiError 响应 / game_dir 的 launch-errors.log），真正的错误信息无法在日志中检索。
4. **无落盘**：日志只存内存环形缓冲（2000 条），崩溃/退出即丢；手动 `POST /diagnostics/dump` 才落盘，用户不会主动触发。
5. **Tauri 主进程无日志**：src-tauri 全部用 `eprintln!`，后端 spawn 失败/被杀/插件网关错误无落盘。
6. **前端无内容级查看**：只能导出文件后自己开编辑器找，无搜索/过滤/级别着色。

## 决策

### 1. 请求日志：只记录失败请求（app.rs）

- 自定义 `on_response` 闭包：`status >= 400` 时 `Level::ERROR` 记一条 `request failed: status=xxx latency=xxms`；正常请求静默。
- 自定义 `on_failure`：连接级错误（无响应）记 ERROR。
- `main.rs` EnvFilter 改回 `"info"`（不再放行 tower_http=debug）。

### 2. 日志格式：简洁结构（main.rs）

- `with_target(false)` + `with_span_events(FmtSpan::NONE)`：`2026-08-15T20:28:22.316073Z ERROR request failed: status=404 latency=0ms`，无 span 上下文与长 target。

### 3. 业务日志补点

- 启动（`endpoints/instance.rs` launch）：成功 `info!(instance, pid, "launch: game started")`；失败 `error!(instance, error, "launch: failed")`。
- 安装（`services/install_tracker.rs` start 统一出口）：completed/cancelled/failed 各记一条（含 instance/kind/error）。

### 4. 后端持续落盘（trace.rs FileLog）

- `FileLog`：`{BaseDir}/logs/qomicex-backend.log` 追加写入；`trace_append` 双写（内存缓冲 + 文件）。
- 超 5 MiB 轮转（重命名带时间戳），保留最近 10 份，防无限增长。
- `AppState::build` 注册 `init_file_log`。

### 5. Tauri 侧日志落盘（src-tauri/logger.rs）

- 新增 `logger.rs`：`tauri_log!` 宏 → `{BaseDir}/logs/qomicex-tauri.log` 追加 + 回显 stderr。
- 替换 lib.rs / plugin_gateway 全部 `eprintln!`（后端 spawn/杀掉/提取失败、网关、WASM 插件日志）。
- src-tauri 新增 `chrono` 依赖（与后端一致，仅 `clock` feature）。

### 6. 前端日志查看器（LogTab）

- 后端新增 `GET /api/logs/content?path=<path>`：读取日志文件内容，仅允许 logs 目录内文件，超 2MB 截断尾部（`truncated` 标志）。
- `LogTab` 内嵌预览面板：点击文件行打开；搜索（命中高亮）、级别过滤（全部/错误/警告/信息）、错误红色/警告黄色/信息默认着色、展开高度切换、关闭。
- `src/api/logs.ts` 加 `getLogContent`。

### 7. 前端 console 日志上报（构建版可查）

- 后端新增 `POST /api/logs/frontend`（body `{level, message}`）：写入 trace 缓冲 + 落盘文件，前缀 `[frontend:level]`。
- `App.tsx` 改造 `setConsoleLevel` 拦截器：包装 console 方法，按 logLevel 过滤后显示 + 上报（`reportFrontendLog`，失败静默）。
- 级别语义修正为 tracing 标准：`shouldLog(lvlIdx) = lvlIdx >= idx`（logLevel=info 上报 log/warn/error，隐藏 debug/trace；调高 debug/trace 全报）。
- 构建版 Tauri 无控制台时，前端 console 日志（含插件、updater 等）仍可在 DebugTab 实时日志 / 日志查看器 / qomicex-backend.log 中查看。

### 8. 子模块日志统一接入（core / connector / downloader）

诊断：三个 submodule 日志原本实际不可用——core 裸 `eprintln!/println!` 无级别且 stdout 不被捕获；connector 的 `log::info/warn/error!` 无 logger 初始化而静默；downloader 的 `DownloadEvent::Log` 无订阅者而静默。

- **tracing-log 桥接**（main.rs）：`tracing_log::LogTracer::init()` 把 `log` crate 事件（connector 的 `log::info!/warn!/error!`）转发进 tracing → trace 缓冲 + 落盘。实测建房间出现 `INFO 创建房间: 端口 25565`、`INFO 启动 EasyTier 实例`、`WARN manual reconnect task done ...` 等。
- **stdout+stderr 双捕获**（trace.rs `start_io_capture`）：core 的 `println!`（stdout，安装流程进度/FTB 日志）与 `eprintln!`（stderr）都被捕获进日志体系，带 `[stdout]/[stderr]` 来源标记。
- **downloader 事件转发**（state.rs）：AppState::build 全局订阅 `DownloadEvent::Log`，按级别写 `[downloader:Level]` 进 trace。实测出现 `[downloader:Info] 探测完成`、`[downloader:Info] 动态拆分`。
- 不改三个 submodule 代码，后端一处打通。

## 备选方案

### 方案 保留 DEBUG 请求日志只调格式
- 优点：改动小。
- 缺点：噪音依旧占缓冲，真正问题仍被淹没。
- 为何不选：用户明确痛点就是"全是重复无用信息"。

### 方案 日志分级到独立文件（error.log / access.log）
- 优点：按级别隔离。
- 缺点：增加文件数量与复杂度；当前缓冲+单文件已满足提取需求。
- 为何不选：用户要的是"能提取出有效信息"，单文件 + 前端过滤已达成。
