# ADR-017：首次启动初始化向导（快速/自定义双模式）

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-15 |
| 决策者 | AI Agent |

## 背景

启动器在全新安装（无 `{BaseDir}/QML/settings.json`）时没有任何引导流程，用户直接进入主界面，语言/主题/Java/内存/目录等关键初始化项全部留默认。需求：**启动器第一次启动时显示设置向导**，强制完成一系列初始化数据后再进入主界面，且区分「快速设置」与「自定义设置」两种模式。

## 需求澄清结果

- **触发**：后端 `SettingsResponse` 新增 `initialized` 字段；全新安装（settings.json 不存在）→ `Some(false)` → 前端显示向导；向导完成保存 `Some(true)`。老用户升级（settings.json 存在但无该字段）→ `load_settings` 补 `Some(true)`，不打扰。
- **两种模式**：
  - 快速设置：语言、主题（深/浅色）、Java、内存。
  - 自定义设置：以上全部 + 下载源（游戏文件源/模组源，测速选优）、数据目录、游戏目录。
- **Java 规则**（两种模式一致）：深度扫描（`scanRuntimes('deep')`），必需 Java 8 / 17 / 21 三档齐全；任一缺失 → 内嵌下载（复用 `getJavaDownloadCatalog` + `startJavaDownload` + 轮询 `getJavaDownloadProgress`，完成后 `refreshCustomRuntimes`），齐全后"下一步"才可用。
- **可跳过性**：强制完成，无关闭/跳过按钮。
- **UI 形态**：全屏向导页（`fixed inset-0 z-[9998]`，SplashScreen 之下），带步骤进度条。
- **语言**：向导内选择语言立即切换向导 UI（`setLanguage` 即时生效）。
- **默认值**：沿用现有系统默认（数据目录 `%LocalAppData%/qomicex-launcher`、游戏目录 `~/.minecraft`、下载源官方 0、模组源 Modrinth 0）。

## 决策

### 1. 后端：`initialized` 标志（零新端点）

- `SettingsResponse` 新增 `initialized: Option<bool>`（`settings.rs`）；`Default` 实现 `Some(false)`。
- `load_settings()`：文件存在但字段缺失（老配置）→ 置 `Some(true)`，避免老用户被迫重走向导；仅文件不存在（全新安装）保持 `Some(false)`。
- 复用现有 `GET/PUT /api/settings`，无新端点；前端 `AppSettings` 加 `initialized?: boolean`。

### 2. 前端：全屏向导组件 + App 挂载

- 新组件 `src/components/InitialSetupWizard.tsx`：全屏覆盖层，步骤序列按模式动态（quick 6 步 / custom 9 步：模式 → 语言 → 主题 → [目录 ×2] → [下载源] → Java → 内存 → 完成）。
- `src/App.tsx`：`AppContent` 订阅 `onSettingsChange`，后端就绪且 `initialized !== true` 时打开向导；完成回调关闭。Java 自动检查（`javaChecked` effect）在向导打开期间挂起，向导完成后恢复。
- 主题/语言在向导内即时应用（复用 `setLanguage`、classList + localStorage `qomicex-theme`）。
- 数据目录变更走 `setDataDir`（写 `.qomicex-bootstrap`）；游戏目录/下载源/镜像/内存直接进 settings 保存。

### 3. i18n：submodule 新增 `wizard` 命名空间

- `qomicex-tauri-i18n/src/{zh-CN,en}/wizard.ts` 双语资源 + 两个 `index.ts` 注册，`en` 走 `satisfies TranslationSchema` 编译期结构校验。

## 备选方案

### 方案 前端 localStorage 标志
- 优点：零后端改动。
- 缺点：清浏览器数据/换数据目录即丢失，多窗口不一致；与后端数据目录（可便携/可迁移）语义绑定弱。
- 为何不选：`initialized` 属于应用配置，与 settings.json 一同持久化更可靠，且后端判定"文件缺失=首次"语义最准。

### 方案 只靠 settings.json 是否存在判定
- 优点：无新字段。
- 缺点：auto-select 等写盘操作会让空配置文件提前出现（文件存在但从未完成初始化），且老用户升级时文件必然存在——无法区分"已初始化"与"未初始化"。
- 为何不选：需要显式标志区分升级用户与全新安装。

### 方案 单一步骤向导（无模式区分）
- 优点：实现简单。
- 缺点：不满足"快速/自定义"两种设置模式的需求；快速用户被强制走全部步骤。
- 为何不选：用户明确要求双模式。

## 影响

- 后端：`src-backend/qomicex-backend/src/settings.rs`（`SettingsResponse.initialized` + `load_settings` 兼容逻辑）。
- 前端：`src/api/settings.ts`（类型 + 默认值）、`src/App.tsx`（挂载/联动）、新组件 `src/components/InitialSetupWizard.tsx`。
- i18n submodule：新增 `wizard.ts`（zh-CN/en）+ index 注册（需在 i18n 仓库单独提交推送）。
- 无新依赖、无构建命令变更、无新 API 端点。
