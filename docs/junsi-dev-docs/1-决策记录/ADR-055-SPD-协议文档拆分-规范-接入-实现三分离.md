# ADR-055：SPD 协议文档拆分：规范/接入/实现三分离

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-27 |
| 决策者 | AI Agent |

## 背景

原 specs/spd-protocol.md 为单一 903 行文档，混合了三类性质不同的内容：协议契约（帧/命令/状态码）、接入方法（EasyTier 组网/中心发现/CLI 用法）、实现验收（golden 示例/Checklist）。单一文件导致：接入方法随 CLI 演进频繁变更，拖累协议契约的稳定性；实现者难以区分"必须遵守的规范"与"可选参考的接入方式"。

## 决策

将 specs/spd-protocol.md 拆分为三个文档：specs/01-protocol.md（协议定义，不可变契约：帧/消息/状态码/命令/房间码/状态机/事件）、specs/02-integration.md（接入方法：EasyTier 组网、hostname 约定、统一流程、CLI 使用）、specs/03-implementation.md（参考实现：golden 字节示例、命令速查表、实现 Checklist）。README.md 改为索引，链接三个文档。拆分依据：内容稳定性分层——协议契约应冻结，接入方法随生态演进，实现清单是验收工具。

## 备选方案

### 方案 保持单一文件
- 优点：无迁移成本
- 缺点：接入方法变更会反复触碰协议契约，版本历史混乱；实现者难辨规范与参考
- 为何不选：未说明

### 方案 两分法（规范+接入）
- 优点：比三分法文件更少
- 缺点：golden 示例与 Checklist 与协议定义强相关，拆出后规范可读性下降
- 为何不选：未说明
