# ADR-073：插件扫描跳过升级快照与临时目录

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-09-11 |
| 决策者 | AI Agent |

## 背景

插件升级时 snapshot_existing_dir 把旧版本目录改名为 `{id}.bak-{version}` 以便回滚。scan_plugins 本应跳过这些内部目录，但判定写成 `n.starts_with(".bak-")`，而快照名以插件 id 开头，前缀恒不匹配 → 快照目录连同其 manifest.json 被扫成第二条同 id 记录，UI 显示多个重复插件卡。commit 7ca584a 声称修复但用错了前缀。

## 决策

在 scan_plugins 抽出并调用 `is_internal_plugin_dir(name) = name.starts_with('.') || name.contains(".bak-")`，统一跳过升级快照 `{id}.bak-{version}` 与临时目录 `.{id}.tmp-*` / `.{id}.rollback-*`。补回归单测 internal_dir_detects_snapshot_and_temp 断言该谓词（已验证未修复时失败、修复后通过）。

## 备选方案

### 方案 仅把 starts_with 改为 contains(".bak-")
- 优点：改动 1 字符级
- 缺点：遗漏临时目录 .{id}.tmp-* / .{id}.rollback-*；语义仍脆弱
- 为何不选：舍弃

### 方案 扫描后按 manifest.id 去重
- 优点：不依赖目录命名
- 缺点：缓存与排序仍不确定，且要按 id 归并两条记录，逻辑更重；根因是目录本不该被扫
- 为何不选：舍弃

### 方案 抽出 is_internal_plugin_dir 谓词统一判定
- 优点：覆盖快照与临时目录；可单测；命名语义清晰
- 缺点：无
- 为何不选：采纳
