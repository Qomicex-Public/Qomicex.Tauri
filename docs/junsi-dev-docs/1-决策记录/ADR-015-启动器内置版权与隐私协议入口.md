# ADR-015：启动器内置版权与隐私协议入口

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-08-15 |
| 决策者 | AI Agent |

## 背景

用户要求"在启动器里内置版权与隐私协议信息"。现有设置页「关于」页签已有 10 张卡片（关于、版本信息、许可证、更新、开发者、鸣谢、参考项目、后端依赖、前端依赖、开源协议），无任何版权声明/用户协议/隐私政策入口，也无首次启动同意流程。项目已有 Dialog + ReactMarkdown 渲染长文的现成模式（`AnnouncementDialog`）。

## 决策

在「关于」页签新增「版权与隐私」卡片，含三个条目：

- **版权声明**：点击弹窗（`LegalDialog`）展示内置 markdown 版权文本（© Qomicex 团队 + GPL-3.0 开源声明 + Minecraft/Mojang 商标免责），文本存于 `src/constants/credits.ts` 的 `COPYRIGHT_NOTICE`，便于后续替换。
- **用户协议**：点击用系统浏览器打开 `https://www.qomicex.top/legal/user-agreement`（`USER_AGREEMENT_URL` 常量）。
- **隐私政策**：占位，按钮置灰 + Badge「即将上线」，待页面/文本上线后填充。

不做首次启动强制同意流程（改动面大、本次未要求）。交互遵循现有模式：`openUrl` 外部打开（fallback `window.open`）、Dialog 复用 AnnouncementDialog 的 markdown 滚动样式。

## 备选方案

### 方案 首次启动强制弹窗 + 勾选同意
- 优点：合规上更完整
- 缺点：涉及启动流程改造、同意状态持久化（localStorage）、对用户打扰大
- 为何不选：本次需求只要求"内置信息"，未要求强制同意门槛

### 方案 三项全部跳转外部网页
- 优点：实现最简单
- 缺点：版权声明属于"内置"诉求的核心（软件自带版权归属），放网页与"内置"不符；且 copyright/privacy 页面尚未上线
- 为何不选：用户明确选择"版权弹窗 + 协议跳网页 + 隐私置灰"

### 方案 关于页直接内嵌全文
- 优点：无需弹窗
- 缺点：占用大量页面空间，破坏关于页卡片式布局
- 为何不选：用户明确选择弹窗形式

## 影响

- `src/constants/credits.ts`：新增 `USER_AGREEMENT_URL`、`COPYRIGHT_NOTICE`
- `src/components/LegalDialog.tsx`：新建版权声明弹窗组件
- `src/pages/Settings.tsx`：AboutTab 新增「版权与隐私」卡片与 `LegalDialog` 渲染
- 无后端、无 API、无构建脚本变更
