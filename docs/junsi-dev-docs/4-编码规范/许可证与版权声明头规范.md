## 许可证

本仓库以 **GPL-3.0-or-later** 发布，全文见根目录 [`LICENSE`](../../../LICENSE)。

`GPL-3.0-or-later` 的语义是「GPL v3 或更新版本」（GPL 正文与 FSF 推荐的默认写法），
而不是锁死在 v3。这与仓库各 manifest 的 `license` 字段保持一致：

| 位置 | 值 |
|---|---|
| 根 `LICENSE` | GNU GPL v3 全文 |
| `packages/plugin-ui/package.json` | `GPL-3.0-or-later` |
| `src-backend/qomicex-backend/Cargo.toml` | `GPL-3.0-or-later` |
| `README.md` | 徽章 + `## 📄 License` |

## 源文件声明头

所有纳入范围的源文件**开头**必须带两行 SPDX 短头：

```ts
// Copyright (C) 2026 Qomicex Launcher Contributors
// SPDX-License-Identifier: GPL-3.0-or-later
```

CSS 使用块注释：

```css
/*
 * Copyright (C) 2026 Qomicex Launcher Contributors
 * SPDX-License-Identifier: GPL-3.0-or-later
 */
```

**为何用短头而非 FSF 推荐的长声明**：完整声明约十余行，每个文件都占这么多，会显著
放大 diff 与阅读噪音；SPDX 标识符是行业标准，机读且与 `LICENSE` 全文配合即完整表达
许可。**版权人以项目为单位**（`Qomicex Launcher Contributors`），不随贡献者增减维护。

## 纳入范围

`.rs` / `.ts` / `.tsx` / `.js` / `.mjs` / `.css`，且为 git 跟踪的文件：

- `src/`、`src-backend/`、`packages/`（除下述例外）、`src-tauri/`、`scripts/`
- 根目录配置：`eslint.config.js`、`postcss.config.js`、`tailwind.config.js`、`vite.config.ts`

## 子模块（submodule）

5 个子模块是**独立仓库**，各自持许可证与声明头，本仓只 pin 指针：

| 子模块 | 许可证 | 源文件头 |
|---|---|---|
| `qomicex-core-rust` | GPL-3.0-or-later | `// Copyright (C) 2026 Qomicex Launcher Contributors` + `SPDX-License-Identifier: GPL-3.0-or-later` |
| `qomicex-downloader-rust` | GPL-3.0-or-later | 同上 |
| `qomicex-connector-rust` | GPL-3.0-or-later | 同上 |
| `Qomicex.Updater` | GPL-3.0-or-later | 同上 |
| `qomicex-tauri-i18n` | **MIT** | `// Copyright (c) 2026 Qomicex Public` + `SPDX-License-Identifier: MIT` |

**i18n 刻意不统一为 GPL**：该仓 `LICENSE` 与 `package.json` 一致声明 MIT，改用 GPL 会
改变其既有授权，非本项工作的范围。其头部写法与自身 `LICENSE` 的署名保持一致。

各子仓同样内置 `scripts/add-license-headers.mjs`（`--check` 幂等校验）。子仓没有 CI
workflow，故该校验需人工或后续接入各自仓库的 CI 才会自动阻断。

**改动子模块源文件后**，需在父仓提交一次子模块指针更新，否则父仓仍 pin 旧 commit。

### 已知陷阱：`core.autocrlf`

`qomicex-core-rust` 的本地配置是 `core.autocrlf=false`，而系统级为 `true`。
该仓 **blob 存 LF、工作区是 CRLF**，且 `autocrlf=false` 意味着提交时**不做归一化**——
编辑工具若按工作区行尾（CRLF）回写，会把整个文件重写成 CRLF，产生数百行的
全文件 diff（实测踩到：`Cargo.toml` 37 行变成 37/37）。

其余子仓为 `autocrlf=true`，提交时自动 CRLF→LF 归一，无此问题。

改动该仓文件时的判据：**写回后用 `git diff --numstat` 复核，删除行数应为 0**
（除确实替换的那一行）；非 0 即说明行尾被改写，应改用 LF 写回。

## 例外（有意不加）

以下文件会被 `qomicex create` **原样复制成用户自己的**插件项目（其 `package.json` 为
`private: true` 且无 `license` 字段）。给它们加本项目的版权与 GPL 头会造成**授权误归属**
（等于宣称用户生成的插件版权归本项目且受 GPL 约束），故排除：

- `packages/qomicex-cli/templates/`（15 个源文件）
- `plugins-dev/hello-plugin/`（8 个源文件）

> 依据：`packages/qomicex-cli/src/commands/create.ts` 的 `createCommand` 通过
> `copyReplace(templateDir(tpl), dest)` 把模板复制到用户指定目录。

## 日常使用

新增或改动源文件后：

```bash
pnpm run license:check   # 校验（CI 同款，缺头则失败）
pnpm run license:apply   # 自动补头（幂等，可反复运行）
```

脚本行为要点：

- **按字节写入**，保留每个文件原有行尾。仓库 `.gitattributes` 为 `* text=auto`，工作区
  存在 CRLF 与 LF 混用；统一改写行尾会产生全文件 EOL churn（提交历史失真）。
- **shebang 之后插入**：`scripts/*.mjs` 与 `packages/qomicex-cli/src/index.ts` 以 `#!` 开头，
  注释不能位于其前，否则破坏可执行性。
- **幂等**：开头已带声明的文件跳过。
- **检测为结构判定**：要求声明以注释形式（`//`、`*`、`/*`）出现在文件开头若干行内，
  **不是**全文件子串匹配 —— 脚本自身含 `SPDX-License-Identifier` 字面量常量、
  且 `const SPDX = '...'` 落在首行时，子串匹配都会把「无头文件」误判为已声明
  （两种写法均实测踩到并修正）。
