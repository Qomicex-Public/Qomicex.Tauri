# 实例删除与安装失败回滚

## 删除语义（`src-backend/qomicex-backend/src/services/instance.rs`）

- `try_delete(id) -> Result<Option<GameInstance>, String>`：删除实例记录 + 版本隔离目录 `{game_dir}/versions/{name}`。目录删除失败（Windows 文件被游戏进程/杀软占用）先重试 3 次（间隔 200ms），仍失败 → **恢复实例记录**并返回 Err——否则记录已删、目录残留，会被 `sync_from_disk` 扫描反推成幽灵实例（新 id 复活，实证案例：89756875-946 → 残留 → 285e3f06-427）。
- `delete(id)`：兼容包装，等价 `try_delete(id).ok().flatten()`（旧静默语义，仅存量测试用）。

## 调用方

| 端点 | 行为 |
|------|------|
| `DELETE /api/instance/{id}`（endpoints/instance.rs） | try_delete Err → 500 透传「版本目录删除失败（可能被占用）」，用户可关占用进程后重试 |
| 安装失败回滚（`/instance/{id}/install`，instance.rs runner） | 失败 → try_delete；删除失败 → 保留记录，错误信息追加「实例记录已保留，请手动删除或重试」 |
| 整合包安装回滚（endpoints/modpack.rs 两处） | 同上 |

## 历史问题（2026-09 修复）

原 `delete()` 的 `remove_dir_all` 失败被 `let _ =` 静默吞掉：记录已删、目录残留 → `sync_from_disk` 第 4 步把「JSON 无记录的扫描目录」自动反推成新实例（`GameInstance::default()` 自动生成新 id、loader 为空）。幽灵实例特征：name 与失败安装一致、loader 为空、id 与操作时不同。

## 已知限制

- 安装失败回滚对「给已有实例加装 loader」场景会连带删掉用户实例与隔离目录内的 mods/saves——当前前端唯一调用点（Instances.tsx startInstall）仅在新建实例后触发，够不到（潜在，未修）。
- 幽灵实例清理：手动删除残留实例（DELETE 端点）即可；若目录被占用，错误会明确提示。
