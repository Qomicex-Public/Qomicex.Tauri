## 后端配置

### appsettings.json（构建期生成，不入库）

位置：`src-backend/qomicex-backend/appsettings.json`。**该文件已被 gitignore**，
由 `build.rs` 在每次构建时生成：

1. 以入库模板 `src-backend/qomicex-backend/appsettings.example.json` 为基线；
2. 用环境变量覆盖敏感项（非空时生效）：

| 环境变量 | 对应键 | 机密性 |
|---|---|---|
| `CURSEFORGE_API_KEY` | `CurseForge:ApiKey` | **机密**（GitHub Actions secret） |
| `MICROSOFT_CLIENT_ID` | `Microsoft:ClientId` | 公开值（可覆盖以切换应用） |

模板内容（两个活键；历史死配置已随 issue #159 清理）：

```json
{
  "CurseForge": { "ApiKey": "" },
  "Microsoft": { "ClientId": "91d14170-6eaa-4fec-8d9a-8c7fb36fabf0" }
}
```

**写入策略**：环境变量提供了值时总是重写（保证 CI 注入值不被本地残留文件遮蔽）；
无环境变量且文件已存在时保持不动（尊重开发者本地配置）。

**本地开发**：复制模板为真实文件并填入自己的 key（或用环境变量）：

```bash
cp src-backend/qomicex-backend/appsettings.example.json \
   src-backend/qomicex-backend/appsettings.json
# 然后编辑 appsettings.json 填入 CurseForge.ApiKey
```

**未配置 `CURSEFORGE_API_KEY` 时**：该键为空字符串，构建**照常成功**；依赖它的功能
（模组图标补全、更新检查）优雅降级。发布流水线（`release.yml` / `debug.yml`）与
CI（`ci.yml`）均在**工作流级 `env:`** 注入 secret，未配置时展开为空串并被 build.rs
视为「未提供」。

> ⚠️ 为什么必须保留生成逻辑：`state.rs` 用 `include_str!("../appsettings.json")`
> 在**编译期**读取该文件，文件缺失会导致 `cargo build/test/clippy` 全部失败。
> 改 `build.rs` 前请先读它的头注释。

### 历史安全事件（issue #159）

`appsettings.json` 曾在 `67f5301` 起以明文入库且含**有效的** CurseForge 生产 key，
仓库为 public → 任何 clone 或旧 release 都能获取。现已从版本控制移除，但**git 历史
中的明文不会被本次改动抹除**，止血依赖在 CurseForge 后台轮换该 key 使其失效。

### NativeAOT 发布（历史，已废止）

后端已重写为 Rust（`src-backend/qomicex-backend/`），不再有 .NET；以下为旧 C# 后端
的步骤，仅对 `legacy` 分支有效：

```bash
dotnet publish -c Release \
  -p:LicenseRequired=false \
  -p:IncludeNativeLibrariesForSelfExtract=true
```


## 前端配置

### Vite 代理

`vite.config.ts` 中配置 `/api/*` → `http://localhost:5000`，前端开发时无需手动启动后端（Tauri dev 会自动处理）。

### 严格 TypeScript

`tsconfig.json` 启用：
- `strict: true`
- `noUnusedLocals: true`
- `noUnusedParameters: true`

未使用的变量或参数会导致构建失败。

## 子模块初始化

```bash
git clone --recurse-submodules <repo-url>
# 或
git submodule update --init --recursive
```

子模块:
- `src-backend/Qomicex.Core.AOT/`
- `src-backend/Qomicex.Connector.Part.Scaffolding/`

需要 `QOMICEX_PAT` (Personal Access Token) 获取子模块访问权限。

## 环境变量

| 变量 | 用途 | 默认值 |
|:---|:---|:---|
| `QOMICEX_HOME` | 覆盖数据目录路径 | `%LOCALAPPDATA%/Qomicex` |
| `QOMICEX_PAT` | GitHub PAT 用于子模块 | - |
| `ASPNETCORE_ENVIRONMENT` | ASP.NET 环境 | `Development` |

## 端口分配

| 端口 | 用途 | 说明 |
|:---|:---|:---|
| 1420 | Vite 开发服务器 | 前端 |
| 5000 | ASP.NET Core API | 后端 |

## 数据目录

默认路径: `%LOCALAPPDATA%/Qomicex/QML/` (Windows)

结构:
```
QML/
├── settings.json       # 应用设置
├── accounts/           # 账户 (JSON)
├── instances/          # 实例 (JSON)
├── licenses/           # 许可证令牌
├── skins/              # 自定义皮肤
├── backgrounds/        # 自定义背景
└── logs/               # 后端日志
```

可设置 `QOMICEX_HOME` 环境变量覆盖整个数据根目录。

### 2026-08-22 更新
### 端口与环境变量

| 变量 | 用途 | 默认值 |
|:---|:---|:---|
| `QOMICEX_PORT` | 后端 TCP 监听端口（仅 dev/CI 模式生效） | `5000` |
| `QOMICEX_IPC_PIPE` | QIPC 管道名/路径；设置即启用管道监听 | - |
| `QOMICEX_NO_TCP` | 设为 `1` 关闭 TCP 监听 | - |
| `QOMICEX_HOME` | 覆盖数据目录路径 | `%LOCALAPPDATA%/Qomicex` |
| `QOMICEX_PAT` | GitHub PAT 用于子模块 | - |

**传输层行为（ADR-040，HTTP→IPC）**：

- **release（Tauri 启动器托管）**：Tauri spawn 时注入 `QOMICEX_IPC_PIPE` + `QOMICEX_NO_TCP=1`——后端只走命名管道（Windows `\\.\pipe\qomicex-backend-{pid}`）/ UDS（`$XDG_RUNTIME_DIR/qomicex/backend-{pid}.sock`），TCP 端口彻底消失，不再有端口占用冲突。
- **dev / CI / 测试脚本**：两个变量都不设 → 仅 TCP `127.0.0.1:5000`，与历史行为一致（curl 冒烟、test-api-filters.sh 不受影响）。手动联调 IPC：给 Tauri 与后端进程设同一个 `QOMICEX_IPC_PIPE` 即可。
- 前端运行期由 `initApiTransport()` 探测 `ipc_ping` 自动选路；探测失败自动回落 HTTP。

协议帧格式见 `src-backend/qomicex-backend/src/ipc.rs` 头注释。
