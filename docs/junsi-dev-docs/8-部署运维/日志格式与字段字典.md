# 日志格式与字段字典

最后更新：2026-11-22

所有落盘日志（`{BaseDir}/logs/qomicex-backend.log` 及其轮转文件、`/diagnostics/trace`、
`/api/logs/frontend` 上报）共用同一种行格式。目标：出问题时一分钟内回答「哪次启动、
哪个版本、卡在哪一步、为什么、影响谁」。

## 1. 行格式

```text
<时间戳> <LEVEL> [<service>] startup_id=<id> <message> [key=value ...]
```

真实样例：

```text
2026-11-21T10:03:26.123Z INFO  [backend] startup_id=a1b2c3d4 后端启动 event=app_starting version=1.1.2 pid=23433 os=osx
2026-11-21T10:03:26.451Z INFO  [backend] startup_id=a1b2c3d4 启动完成 event=app_ready listen=http://127.0.0.1:5000 duration_ms=451
2026-11-21T10:03:31.002Z WARN  [downloader] startup_id=a1b2c3d4 段许可被降级 segment_index=3 reason=host-limit
2026-11-21T10:03:31.090Z WARN  [frontend] startup_id=a1b2c3d4 updater: check failed [UPDATE_FETCH] status=0
2026-11-21T10:03:31.100Z INFO  [plugin:plugin.example] startup_id=a1b2c3d4 面板已注册
2026-11-21T10:03:31.120Z LOG   [stderr] startup_id=a1b2c3d4 core: font manifest malformed
```

- **时间戳**：ISO8601 UTC、毫秒精度、`Z` 结尾。本地时间由查看器转换，落盘一律 UTC。
- **级别**：`ERROR` / `WARN` / `INFO` / `DEBUG`，外加 `LOG`（子进程原始 `println!` /
  `eprintln!`、无级别来源）。`LOG` 不等于 INFO，统计时单独成桶。
- **service**：`backend`（tracing 事件，含 connector 经 `LogTracer` 桥接的 `log`）、
  `downloader`、`frontend`、`plugin:<plugin_id>`、`plugin-signature`、`panic`、
  `stdout` / `stderr`（子进程捕获）、`app`（无法归类的原文）。
- **startup_id**：后端进程启动时生成的 8 位十六进制。进程内所有日志（含前端上报、
  下载器事件）都用后端这一次的 id —— 它们跑在这个后端进程的语境里。
- **字段**：`key=value`，snake_case，单位后缀必带（`duration_ms`、`total_bytes`、
  `memory_total_mb`）。空值不输出该字段，不写 `key=`。

## 2. 启动边界事件

| 事件 | 级别 | 含义 |
|---|---|---|
| `app_starting` | INFO | 进程启动，带环境快照：版本、pid、os、arch、data_dir、game_dir、home_dir、cwd、cpu、内存、监听参数 |
| `app_stage` | DEBUG | 已完成的启动阶段（`state`/`prewarm`/`rollback`/`router`/`listen`），带 `elapsed_ms` |
| `app_ready` | INFO | 监听已建立，带 `listen` 与 `duration_ms` |
| `app_start_failed` | ERROR | 启动未完成即退出（panic 或提前返回），带 `stage`、`duration_ms` |

排查顺序固定为：`app_starting` 看环境 → 有没有 `app_ready` → 没有就看最后一个
`app_stage` / `app_start_failed.stage`。

## 3. 字段字典（按域）

| 域 | 字段 | 说明 |
|---|---|---|
| 启动 | `event` `pid` `version` `os` `os_display` `arch` `data_dir` `game_dir` `home_dir` `cwd` `cpu` `memory_total_mb` `memory_available_mb` `log_level` `tcp_enabled` `port` `ipc_pipe` `duration_ms` `stage` `listen` | 见上表 |
| 路径解析 | `game_dir` `abs_dir` `versions_dir` `versions_exists` `path_source` `home_dir` `cwd` | `path_source` = `absolute` / `home` / `relative`；相对路径按用户主目录展开，**不按进程 cwd**（macOS 从 Finder 启动时 cwd 是 `/`） |
| 版本扫描 | `mode`（`fast`/`full`）`skip_jar_probe` `cache_hits` `cache_misses` `elapsed_ms` `count` | |
| 内存 | `total_bytes` `raw_available_bytes` `used_bytes` `free_bytes` `normalized_available_bytes` | 平台返回值不可信时打 `memory_stats_implausible`（每进程一次） |
| 更新 | `event`（`update_check_started`/`update_decision`）`current` `channel` `candidate` `should_update` `reason` `channel_switch` `duration_ms` | `reason`：`update-available` / `up-to-date` / `not-newer` / `channel-mismatch` / `no-version` / `dev-build` |
| IPC | `conn_id` `transport`（`qipc-pipe`/`qipc-unix`）`peer` `phase`（`read_request`/`parse_uri`/`read_body`/`write_headers`/`write_body`）`err_kind` `os_error` `will_retry` `impact` | 对端正常断开记 `DEBUG ipc_connection_closed`；异常记 `WARN ipc_connection_error` |
| 下载 | `segment_index` `total_segments` `total_bytes` `reason` | 由 qomicex-downloader 的事件透传（字段改造待子模块单独排期） |

## 4. 级别约定

按「是否预期、是否影响用户」定级：

- 对端主动断开（Broken pipe / Connection reset / EOF）→ `DEBUG`，`impact=none`。
- 有兜底并成功的降级（镜像回退、通道守卫拒绝）→ `WARN`，必须带 `reason`。
- 业务预期内的空结果（无更新、实例不存在）→ `INFO`，不用 `WARN`。
- 真正的失败（写盘失败、协议错帧、启动失败）→ `ERROR`，带 `err`/`err_kind`。

## 5. 脱敏

- 所有非 tracing 日志经 `trace::trace_event` 统一走一遍 URL 脱敏（去 userinfo/query）。
- tracing 字段名命中 `password` / `token` / `access_token` / `refresh_token` /
  `authorization` / `secret` / `client_secret` / `api_key` / `apikey` / `cookie` /
  `session` / `passwd` → 值替换为 `[REDACTED]`。
- 控制字符（`\x1b` 等）在写盘前转义，避免日志行伪造终端输出。
- 路径类字段按原样记录（排障必需），对外上报时由上报链路自行裁剪。

## 6. 落盘与保留

当前实现：单文件 5 MiB 封顶，滚动保留 10 份（`services/trace.rs`）。分级保留
（ERROR 30 天 / WARN 14 天 / INFO 7 天）尚未实现，需要先确定产品策略，见 ADR-140。
